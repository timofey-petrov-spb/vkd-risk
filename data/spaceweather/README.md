# Базы данных космической погоды

Всё скачано 17.09.2026 и лежит рядом. Сеть на хакатоне может подвести,
поэтому у каждого живого источника есть запасной путь.

Порядок один и тот же: **живой запрос → кеш `data/cache/` с записанным
временем получения → снимок репозитория как последний резерв → «данных
нет»**. Снимок никогда не выдаётся за свежее наблюдение: в статусе источника
печатается, откуда взяты данные и какова их давность. Из файлов этого
каталога последним резервом служит только `goes_protons_3day.json`
(раздел 4); снимок TLE берётся из `data/orbit/` с записью манифеста
(раздел 2), снимка Kp нет вовсе (раздел 4, «Живой Kp»), а
`igrf14coeffs.txt` сервисом не читается (раздел 3).

## 1. `kp_ap_sn_f107.txt` — главный файл, 5,5 МБ

**Что:** Kp, ap, Ap, число пятен и F10.7 в одном файле, посуточно **с 1932 года
по 16.09.2026**. 34 633 строки.

**Источник:** GFZ Helmholtz Centre Potsdam, `kp.gfz.de`. Лицензия CC BY 4.0,
кроме чисел пятен — CC BY-NC 4.0.

**Формат:** фиксированная ширина, колонки по порядку:

```
YYYY MM DD  days  days_m  Bsr  dB  Kp1..Kp8  ap1..ap8  Ap  SN  F10.7obs  F10.7adj  D
```

`Kp1..Kp8` — Kp за восемь трёхчасовых интервалов суток UT, `ap1..ap8` — то же
в линейной шкале ap. `Ap` — суточное среднее. `SN` — число пятен.
`F10.7obs` — наблюдённый поток, `F10.7adj` — приведённый к 1 а.е.
`D` — признак окончательности: 0 предварительные, 1 Kp окончательный,
2 и Kp, и SN окончательные.

**Зачем нам:** `F10.7` и `Ap` — прямые входы модели атмосферы
ГОСТ Р 25645.166-2004. `Kp` — признак геомагнитной возмущённости, влияет на
границу проникновения частиц. **В дозу Kp не переводится**, см.
`docs/ZAMYSEL.md` раздел 6.

**Как используется в сервисе (с 19.09.2026):** поставщик истории
`experiments/stub_history.py` (`gfz_archive_kp_samples`) читает из этого файла
окончательный ряд Kp за 1 мая — 30 июня 2024 (488 трёхчасовых интервалов,
`D = 2` → качество `final`) для **разбора после факта** и как факт «буря в
окне» в экспериментах Т5 (`experiments/forecast_lines.py`,
`scripts/make_examples.py`). Времени публикации по интервалам у ряда нет,
поэтому в строгом «прогнозе из прошлого» все эти интервалы исключаются
отсечкой с причиной (CONTRACT §10: Kp GFZ окончательный — только проверка
после факта). Каждая сырая запись несёт строку файла, SHA-256 файла, признак
`D` и дату снимка. Сверка с DONKI: строка `2024 05 10`, интервал 15–18 UT,
Kp6 = 7,667 = `allKpIndex` карточки `2024-05-10T15:00:00-GST-001` с
`observedTime` 18:00Z (observedTime DONKI — конец интервала).

**Состояние на 16.09.2026:** F10.7 = 99,7 · Ap = 8 · SN = 28. Активность
умеренно низкая.

## 2. `iss.tle` — справочный снимок орбиты станции

**Источник:** CelesTrak, NORAD 25544. Этот файл — **справочная копия** и в
расчёт не идёт: у него нет записи о получении (время файла на свежем клоне
равно времени клонирования, а не скачивания). Откуда орбита берётся на самом
деле — ниже, «Как сервис получает TLE».

**Разобрано:**

| параметр | значение |
|---|---|
| наклонение | 51,6307° |
| оборотов в сутки | 15,491523 |
| период | 93,0 мин |
| большая полуось | 6797,3 км |
| **высота средняя** | **419,2 км** |
| эксцентриситет | 0,0004826 |

**Важно для расчёта.** Высота 419 км и наклонение 51,6° — справочные числа.
Дозовые таблицы прил. К ОСТ 134-1044-2007 сервисом не используются;
траекторию считает модуль A3 (SGP4/WGS72), а вход в таблицы прил. А идёт по
L и B/B_0 эксцентричного диполя, а не по высоте и наклонению.

### Как сервис получает TLE (с 19.09.2026)

Порядок — в `experiments/stub_sources.py` (`tle_latest`), адреса — в
`config/settings.toml`, `[sources.urls].tle`; тайм-аут `[sources].timeout_s`
= 6 с на адрес.

1. **Цепочка из трёх адресов**, по порядку настроек; в расчёт идёт первый
   разобранный ответ, его адрес — в манифест орбиты, отказавшие
   перечисляются в статусе источника:
   `https://celestrak.org/NORAD/elements/gp.php?CATNR=25544&FORMAT=TLE` →
   `https://api.wheretheiss.at/v1/satellites/25544/tles` →
   `https://tle.ivanstanojevic.me/api/tle/25544`.
   CelesTrak — первичный адрес; 19.09.2026 он давал тайм-аут, поэтому
   резервы обязательны. Тело ответа сохраняется как есть
   (`data/cache/tle_raw_<хост>.txt` + SHA-256), нормализованные три строки —
   производная запись со ссылкой на исходную.
2. **Кеш** `data/cache/` с записанным временем получения и давностью
   (раздел 7).
3. **Снимок репозитория — последний резерв**, и это `data/orbit/iss.tle`
   (файл Codex, область A3) вместе с записью `data/orbit/manifest.json`
   (адрес, `fetched_utc`, SHA-256): байты сверяются с манифестом, в статусе
   пишется «снимок репозитория data/orbit/iss.tle, получен … с
   celestrak.org (манифест A3), давность …». Файл `data/spaceweather/iss.tle`
   в этой цепочке **не участвует** — у него нет свидетельства получения.

Снимок стареет: при давности больше `tle_max_age_days` (3 сут) относительно
обеих границ горизонта орбита объявляется недоступной, заглушка не
подставляется (Р-О2). Перед защитой снимок обновляет владелец репозитория.

В исторических режимах TLE не нужен: орбита строится по OEM NASA/JSC из
реестра A1 (`data/source_registry_2024/nasa_oem/`, файлы Codex).

## 3. `igrf14coeffs.txt` — модель магнитного поля

**Что:** коэффициенты сферических гармоник IGRF-14, степень до 13,
эпохи с 1900 по 2030, в нТл. Для степеней до 8 даны скорости векового хода.

**Источник:** IAGA через NOAA NCEI.

**Внимание (19.09.2026): сервис этот файл не читает.** Единственный его
потребитель — ранняя демонстрация `experiments/demo_pipeline.py` (ось
диполя), помеченная «не эталон».

**Откуда поле берётся на самом деле.** Модуль |B| вдоль трассы считает
модуль A3 по коэффициентам из `data/orbit/` (файлы Codex, область А):
`IGRF13.shc` для дат 2024 года и `IGRF14.shc` для текущих, хеши — в
`data/orbit/manifest.json` и проверяются при загрузке; вне таблицы
коэффициентов — отказ без экстраполяции. Оттуда же берутся ось и смещение
центра эксцентричного диполя для L и B/B_0
(`vkd/assess/magcoords.py`, R11). Область аномалии на карте экрана
(`app/viz.py`) считается отдельно на сетке 4° встроенными коэффициентами
`ppigrf`.

**Зачем нужно поле:** через модуль |B| — **геометрия
Южно-Атлантической аномалии**. Аномалия определяется физически, как область
пониженного поля, а не нарисованным контуром.

Связано с приложением Д ОСТ 134-1044-2007 (геоцентрические и L-B координаты).

**Помнить:** аномалия дрейфует на запад со скоростью **0,3° в год**, около 10°
с момента создания моделей поясов. ECSS-E-ST-10-04C называет это прямо
и в скобках указывает применение — выход космонавта.

## 4. `goes_protons_3day.json` — протонный поток, трое суток

**Что:** интегральный поток протонов GOES-18 по порогам энергии, 6880 записей.
Поля: `time_tag`, `satellite`, `flux`, `energy`.

**Источник:** NOAA SWPC.

**ОСТОРОЖНО.** GOES меряет на **геостационарной орбите**, вне магнитосферной
защиты. Переносить его напрямую на космонавта на низкой орбите **нельзя**:
на наклонении 51,6° геомагнитное обрезание отсекает большую часть протонов
вспышки, кроме приполярных участков.

Правильное применение: GOES показывает, **что событие идёт**. Поток у
космонавта сервис не вычисляет: пересчёт через функцию проникновения
(прил. Ж ОСТ 1044) не сделан, а доступность канала на трассе выражена
отдельной величиной «минут доступности протонов ≥10 и ≥100 МэВ по
обрезанию» — порог по вертикальной жёсткости обрезания A3, без формы
спектра. Снижение обрезания при буре не моделируется.

### Как сервис получает GOES (с 19.09.2026)

Порядок — `experiments/stub_sources.py` (`goes_latest` → `fetch_text`),
адрес — `config/settings.toml`, `[sources.urls].goes`:

1. **живой запрос**
   `https://services.swpc.noaa.gov/json/goes/primary/integral-protons-3-day.json`
   (тайм-аут 6 с); удачный ответ пишется в `data/cache/` вместе со временем
   получения, адресом и SHA-256;
2. **кеш** с показанной давностью — статус «отказ источника: кеш, давность
   N мин»;
3. **снимок репозитория — последний резерв**: этот файл. Время получения
   известно лишь датой (17.09.2026, время суток не записано), поэтому в
   статусе пишется «снимок репозитория …, скачан 17.09.2026 (README; время
   суток не записано), давность не меньше …», а давность самих наблюдений
   считается по `time_tag` записи. Значение из снимка к моменту защиты
   устарело и по правилу свежести GOES (`goes_max_age_min` = 60 мин) даёт
   лишь частичное покрытие — это объявляется, а не скрывается.

Живые запросы делает только режим «Текущая обстановка»; в исторических
режимах наблюдений GOES нет вовсе — архива за 2024 год у нас нет, и это
объявляется отдельной строкой в таблице источников.

Обновить снимок вручную:

```
curl -L "https://services.swpc.noaa.gov/json/goes/primary/integral-protons-3-day.json" -o goes_protons_3day.json
```

### Живой Kp: JSON API GFZ (снимка в репозитории нет)

Наблюдения Kp в текущем режиме сервис берёт запросом к
`https://kp.gfz.de/app/json/?start=…&end=…&index=Kp` за последние **двое
суток** (`experiments/stub_sources.py`, `kp_latest`); в расчёт идёт последнее
значение. Поле `datetime` ответа — **начало** трёхчасового интервала (не
конец, как `observedTime` у DONKI; сверено по файлу раздела 1 за
10.05.2024: 15:00Z → 7,667 = Kp6). Поле `status` переводится в качество:
начинается на `def` → `final` (окончательное), любое другое значение и его
отсутствие → `preliminary` (предварительное), а не «неизвестно молча». Ещё
не завершённый к моменту запроса интервал дополнительно помечается
«интервал … не завершён — предварительная оценка GFZ, значение изменится».
Лицензия CC BY 4.0.

**Снимка Kp в репозитории нет.** Резерв один — кеш `data/cache/`; без сети и
без кеша Kp получает статус «данных нет», и это показывается, а не
подменяется нулём и не выдаётся за «благоприятно». Файл `kp_ap_sn_f107.txt`
(раздел 1) — архивный ряд для исторических режимов и экспериментов, живым
резервом он не служит: его последняя строка датирована 16.09.2026.

## 7. Кеш живых источников `data/cache/` (не в репозитории)

Пишется слоем `experiments/stub_sources.py`. Каждой записи `<ключ>` соответствует
`<ключ>.meta.json`: `fetched_utc` (время получения), `url` (адрес), `sha256` и
`bytes` данных; для TLE — ещё `raw_response_path`, `raw_response_sha256`,
`provider_time`. Сначала пишется meta, затем данные, каждый файл — через
временное имя и `os.replace`. При чтении SHA-256 сверяется: несовпадение или
отсутствие meta означает «время получения неизвестно» — статус так и звучит,
давность не подменяется нулём. Ответ Kp GFZ для ещё идущего трёхчасового
интервала помечается «интервал … не завершён — предварительная оценка GFZ».
