# A1: численные наблюдения GOES за май–июнь 2024

Источник — [NASA CCMC iSWA HAPI](https://iswa.gsfc.nasa.gov/IswaSystemWebApp/hapi/info?id=goesp_part_flux_P5M),
первичный поток `goesp_part_flux_P5M`. Сохранены **65 точных суточных CSV**
за 29.04–02.07 включительно и отдельный исходный JSON схемы. Всего около
4 МБ исходных ответов, без перекодирования. Запас покрывает 48 ч контекста
в начале мая и максимум 8 ч ВКД + 24 ч поиска + 3 ч задержки в конце июня.
Контекст более 48 ч разрешён адаптером, но дополнительный охват до 29.04
не обещан и не восполняется.

`registry.json` / `records.json` используют существующую схему A1 и
`SourceRegistry`; прежние 390 записей основного реестра не менялись.
Каждый выпуск имеет URL запроса, SHA-256, версию по содержимому, время
получения, HTTP-метаданные, границы запроса и ссылку на хешируемую схему.
`Last-Modified`, текущее `stopDate` HAPI и дата измерения не выдаются за
дату исторической публикации. `published_utc` и `available_utc` — **None**.

## Величина и семантика

- `P10` — интегральный протонный поток ≥10 МэВ, `pfu = протон/(см²·с·ср)`.
  [Описание NOAA](https://www.swpc.noaa.gov/products/goes-proton-flux)
  связывает именно этот порог с S-шкалой. Другие столбцы не подставляются.
- `Time` — начало пятиминутного усреднения, поддержка `[t, t+300 с)`:
  [NOAA ATBD18, таблица 7, с.37](https://www.ngdc.noaa.gov/stp/space-weather/online-publications/stp_sii/spades/algorithm-theoretic-basis-documents/atbds_seiss/atbd_seiss18_integral-flux_v1-0.pdf).
  Это интервал измерения, не срок действия прогноза/опасного события.
- Спутник берётся из `satelliteProton`, а не `satelliteElectron`. В проверенных
  майских записях протоны — GOES-18, электроны — GOES-16. Метаданные выпуска
  сохраняют распределение спутников, оригинал — спутник каждой строки.
- HAPI не выдаёт инструментальные флаги качества: `quality='unknown'`.
  Отрицательные значения, fill `-100000`, null, NaN/Inf исключаются; нули
  допустимы только если прямо записаны в источнике. Интерполяции нет.
- NOAA `sci_sgps-l2-avg5m` содержит интегральный **>500 МэВ**, не нужный P10.
  Он используется только для дополнительной проверки меток времени в
  `validation/`, не как источник ≥10 МэВ.

## Фактический охват

18 400 пригодных значений на 65 суток; 12 присутствующих, но непригодных
строк. С учётом отсутствующих временных меток — 320 пропущенных ячеек.
За **май–июнь охват 98,3436%**, 10 непрерывных разрывов. Самый большой:
24.06 21:25 — 25.06 12:00 UTC. Все границы и дневные максимумы находятся
в [coverage.json](coverage.json); заполнения пропусков «спокойным» фоном нет.

| Контроль, начало UTC; горизонт 32 ч | Временной охват |
|---|---:|
| 01.05 00:00 | 98,4375% |
| 03.05 12:00 | 100% |
| 10.05 19:00 | 100% |
| 20.05 12:00 | 100% |
| 01.06 12:00 | 100% |
| 25.06 00:00 | 60,15625% |
| 30.06 23:59 | 99,21875% |

100% означает присутствие чисел на временной сетке, не подтверждённое
качество прибора и не полноту всех обязательных линий рекомендации.
Контроль P10: 10.05 17:45 — 206,91934204101562 pfu;
08.06 08:00 — 1028,5311279296875 pfu. Эти значения проверяют чтение
реальных данных, но не служат независимой валидацией физической модели.

## Режимы и повторение

`history_snapshot(Request(... mode='history_review' ...))` возвращает
численные значения, покрытие, исходные байты и реестр. В
`history_forecast` **все эти выпуски исключены**, даже для наблюдений до
отсечки: историческая доступность именно сохранённой версии не доказана.
Факты датированных уведомлений и прогнозы NOAA остаются отдельными линиями.

Офлайн-проверка из корня проекта:

```sh
python -m vkd.sources.verify_goes_archive
python -m pytest tests/sources/test_goes_archive.py -q
```

Команда получения для новой версии, с сетью, не перезаписывает существующую:

```sh
python -m vkd.sources.acquire_goes_archive --output data/goes_2024_new_version
```

Нет новых runtime-зависимостей. Офлайн-парсер использует стандартную
библиотеку, явное получение — уже используемый проектом `requests`.
Численный ряд также доступен в [NASA CLEAR benchmark](https://ccmc.gsfc.nasa.gov/swxcoe/clear/benchmark.php),
но в репозиторий взяты меньшие исходные ответы HAPI с идентификаторами спутника.
