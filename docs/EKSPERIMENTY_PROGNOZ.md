# Эксперимент Т5: прогнозные линии строгого режима, 1 мая — 30 июня 2024

Сгенерировано `experiments/forecast_lines.py` (2026-09-18 23:52Z); сохранённые расчёты по каждому окну — `examples/experiments/forecast_lines.json`. Отсечки каждые 6 ч, окна по 360 мин со сдвигом 0/6/12/18 ч; всего окон 964 (событие 48, контроль 916). Условия — тот же `assess_window`, что в приложении, по записям, опубликованным до отсечки; факт — окончательный ряд Kp GFZ и карточки SEP после события, только для проверки.

Настройки: `config/settings.toml` — пороги приложения `kp_check = 7` (условие и факт «буря»), `goes_p10_warning_pfu = 10`, `[history].enlil_kp_fields = kp_90`, `[history].enlil_publication_lag_min = 60`.

## Что считается

- каждая линия считается против своей величины: линии по буре — против факта «буря в окне», линии по протонному событию — против факта «протонное событие в окне» (договор: бурю и протонное событие не складывать);
- **факт «буря в окне»**: Kp ≥ 7 в 3-часовом интервале окончательного ряда GFZ (`data/spaceweather/kp_ap_sn_f107.txt`, D = 2), пересекающем окно;
- **факт «протонное событие»**: карточка SEP DONKI по наблюдательному прибору, начало в [начало окна − 24 ч, конец окна);
- **попадание** — условие есть и факт есть; **пропуск** — условия нет, факт есть; **ложная тревога** — условие есть, факта нет;
- линия `noaa` считается только там, где выпуск 3-day forecast есть в архиве (разрыв 15.05–16.06 исключён из её счёта);
- базовая линия получает окончательный Kp по концу интервала без проверки публикации — ей дано больше, чем строгому режиму;
- линия `enlil` в основных таблицах — с оценкой Kp из настроек приложения (`[history].enlil_kp_fields = kp_90`); публикация прогона = завершение + 60 мин, не раньше подачи анализа (R10; анализы, поданные в 2025 году, отсечкой исключены); другие варианты оценки Kp — в таблице чувствительности ниже;
- карточки событий SEP DONKI в строгом режиме не используются (CONTRACT §10): условия по протонному событию — только из датированных уведомлений.

## Чувствительность линии ENLIL к выбору оценки Kp прогона

Условие ставится при «Kp до …» ≥ 7; «Kp до» — максимум из выбранных полей прогона WSA-ENLIL. Все столбцы — против факта «буря».

| поля Kp | событие: попад./проп./ложн. (enlil) | событие: система по буре | контроль: попад./проп./ложн. (enlil) | контроль: система по буре |
|---|---|---|---|---|
| kp_90 | 27 / 0 / 18 | 27 / 0 / 18 | 0 / 5 / 6 | 0 / 5 / 16 |
| kp_18+kp_90+kp_135+kp_180 | 27 / 0 / 18 | 27 / 0 / 18 | 1 / 4 / 69 | 1 / 4 / 79 |
| kp_180 | 27 / 0 / 18 | 27 / 0 / 18 | 1 / 4 / 69 | 1 / 4 / 79 |
| kp_135 | 27 / 0 / 18 | 27 / 0 / 18 | 1 / 4 / 37 | 1 / 4 / 47 |

Выбор для приложения: `kp_90` — типичная оценка прогона; верхняя оценка при южном поле (kp_180) остаётся в тексте условия. Основание — столбцы «контроль»: ложные тревоги линии ENLIL и системы.

## Границы

- Архива наблюдений GOES за 2024 нет: факт протонного события — по карточкам SEP DONKI с конвенцией 24 ч, не по потоку;
- буря в окне определяется по Kp ≥ 7; бури ниже порога не считаются событием ни для условий, ни для факта;
- прогнозы ENLIL и NOAA — внешние; линии `system_*` показывают, что видит пользователь, и не приписывают их заблаговременность команде;
- доступность прогона ENLIL к отсечке принята по политике R10 (завершение прогона + запас, не раньше подачи анализа), не доказана датированным выпуском;
- одно выраженное событие за период: статистика по нему — разбор случая, не оценка вероятностей;
- ложные тревоги после начала события (условие держится 24 ч после протонного события и на длительность прогона ENLIL) — следствие конвенций, они названы.
