# Два вопроса, которые может решить только владелец

Собрано после слияния третьего круга; пункт 1 переписан 19.09.2026 в 04:50 UTC (пятый круг)
по состоянию на момент работы. В шапке прежней редакции стояло «около 07:00 UTC» — это не
сходится с журналом (`journal/tim.md`: слияние четвёртого круга записано в 04:30 UTC, то есть
позже третьего) и, судя по всему, было местным временем машины (UTC+3). Точное время той записи
восстановить нельзя, поэтому просто помечаю.

## 1. Развёрнутый сервис: состояние на 19.09.2026, 04:50 UTC

**Адрес отвечает.** Проверено прямыми HTTP-запросами из этой сессии (браузер не использовался):

| запрос | результат |
|---|---|
| `GET https://vkd-risk.streamlit.app/healthz` | **200**, тело `{"status":"ok"}`, 0,5 с |
| `GET https://vkd-risk.streamlit.app/` | **303** на `share.streamlit.io/-/auth/app?redirect_uri=…` — обычный обмен сессионной cookie площадки; с браузерным `User-Agent` и приёмом cookie тот же адрес отдаёт **200** за 1,96 с (ставятся `streamlit_session`, `_streamlit_csrf`) |
| какая сборка развёрнута | площадка собирает из `origin/main` = `925f923`; локальный `main` на момент проверки был впереди на один коммит, и тот коммит — только `docs/presentation/SLIDES_DRAFT.md`, кода не касается |

То есть «двадцать минут „Your app is waking up“», о которых говорила прежняя редакция этого
пункта, сейчас **не воспроизводится**: площадка отвечает за доли секунды, и развёрнутый код
совпадает с тем, на котором зелёные проверки.

**Чего эта проверка НЕ доказывает, и это важно.** Streamlit рисует экран по websocket уже после
загрузки страницы, поэтому HTTP-ответ говорит только о том, что адрес жив и контейнер отвечает.
Открывается ли экран, считает ли он и переключаются ли режимы — так не проверяется, а браузерную
панель в этом круге использовать нельзя. **Это остаётся ручной проверкой владельца:**
`docs/design/CHECKLIST_PREDEFENCE.md`, пункты 6–9 (разбудить за 15 минут, пройти три сценария,
скачать архив, открыть с телефона).

**Если при вашей проверке экран всё-таки не поднимется (2 минуты).** Открыть
https://share.streamlit.io, у приложения нажать «Manage app» в правом нижнем углу страницы
приложения, посмотреть журнал. Если в журнале ошибка — прислать мне её текст. Если журнал просто
тянется — нажать «Reboot app».

**Что было измерено со стороны кода** — измерения прежней редакции, на коммите третьего круга;
пятым кругом они не пересчитывались, кроме числа проверок: холодный старт через ту же точку
входа — 2,3 с без исключений, строгий исторический режим — 1,3 с без исключений, новых
зависимостей у кода Codex нет, расхождений регистра в путях нет (проверены 29 ссылок), данных
49 МБ при рабочем дереве 144 МБ и 776 файлах. Автоматических проверок тогда было 408,
сейчас **450 плюс 691 подпроверка** (прогон 19.09 на `925f923`, код возврата 0).

## 2. В публичном репозитории лежат тексты стандартов

**Что есть.** После перевода репозитория в публичный доступ вместе с кодом опубликованы файлы
в `docs/istochniki/`: ECSS-E-ST-10-04C Rev.1 (3,2 МБ), ECSS-E-ST-10-12C (0,9 МБ),
ГОСТ Р 25645.167-2005 (3,2 МБ), ОСТ 134-1044-2007 (1,3 МБ) и другие — суммарно около 28 МБ.

**Почему это вопрос.** Тексты стандартов защищены авторским правом их издателей; выкладывать их
целиком в открытый доступ обычно нельзя. Для оценки работы они не нужны: жюри проверяет, что мы
правильно применили формулы и сослались на источник, а не что у нас лежит копия документа.
Побочно это половина веса репозитория, то есть и более долгая пересборка окружения на площадке —
именно ею прежняя редакция пункта 1 объясняла долгое пробуждение сервиса.

**Что предлагаю.** Убрать эти файлы из репозитория и оставить вместо них список источников:
обозначение, название, редакция, раздел или таблица, откуда взята формула, и адрес, где документ
получают официально. Все ссылки в коде и документах уже указывают на разделы и таблицы, а не на
сами файлы, поэтому прослеживаемость не пострадает. Локальные копии остаются у вас на диске.

Команды (выполняю по вашему слову, одна минута):

```bash
git rm --cached docs/istochniki/*.pdf docs/istochniki/*.docx
printf 'docs/istochniki/\n' >> .gitignore
git commit -m "Тексты стандартов не публикуются: остаётся список источников с разделами и адресами"
git push origin main && git push gitverse main
```

Замечание: из истории репозитория файлы при этом не исчезают, но в текущем состоянии и в архиве
загрузки их не будет. Полная очистка истории — отдельная операция, до защиты её делать не стоит.

**Решение за вами:** это публикация чужих материалов, и отменять её должен владелец репозитория.
