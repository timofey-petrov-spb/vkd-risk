Ни одного теста, ни `.env.example`, ни `config.toml`, ни CI нет; `pytest` на машине Тимофея не установлен; README и CLAUDE.md/AGENTS.md до сих пор описывают отменённый стек C++/Qt. Инженерная работа по Т1, Т6, Т7, Т8 — это не исследование, а строительство: слой источников с сырыми записями и дедупликацией, конфигурация вне кода, тесты на инварианты, воспроизводимая выгрузка и дисциплина совместной работы двух ассистентов.

Фактическая проверка источников по сети (все URL ниже запрошены curl с этой машины) дала четыре результата, которые меняют план. Первое: CelesTrak не даёт исторических элементов МКС за май–июнь 2024 (параметр EPOCH игнорируется, архивы заканчиваются 2004 годом по закону 108-136), но NASA JSC TOPO публикует датированные OEM-эфемериды МКС в открытом S3-хранилище `nasa-public-data/iss-coords/<дата>/ISS_OEM/` — 13 файлов за май и 12 за июнь 2024, каждый с `CREATION_DATE`, шагом 240 с и охватом 15 суток; это даёт историческую орбиту с меткой публикации без учётной записи Space-Track, но требует правки CONTRACT.md раздел 10 (там написано «из TLE того периода»). Второе: склад SWPC `ftp.swpc.noaa.gov` с этой сети недоступен (шесть запросов, таймаут 60 с каждый), однако датированные выпуски SWPC за 2024 лежат на NGDC: `swpc-products/daily_reports/3day_forecast/2024/05/202405100030three_day_forecast.txt` с отметкой `Issued: 2024 May 10 0030 UTC` и разбивкой Kp по 3 ч на трое суток — это и есть «датированный прогноз» для строгого replay. ### 2. Слой источников: единый интерфейс, сырые записи, дедупликация, квоты — с измеренными объёмами и наблюдённым троттлингом

Предлагаемый интерфейс (пакет `vkd/sources/`, владелец Codex):

```
class Source(Protocol):
    source_id: str            # "celestrak_gp", "swpc_goes_int", "gfz_kp", "donki_notif", "ngdc_3day", "nasa_oem", "socrates"
    cadence_s: int            # частота публикации источника
    max_age_s: int            # после этого — статус STALE
    def fetch_live(self) -> RawRecord
    def fetch_archive(self, start_utc, end_utc) -> list[RawRecord]
    def parse(self, raw: RawRecord) -> list[EnvironmentSample | EventInterval | Conjunction]
    def status(self, now_utc) -> SourceStatus
```

`RawRecord` = байты ответа + сайдкар JSON: `url`, `fetched_utc`, `http_status`, `etag`/`last_modified` (у S3 NASA и NCEI есть Last-Modified), `content_sha256`, `bytes`, `source_version` (для NCEI — версия файла из имени `v3-0-2`/`v3-0-3`; для DONKI — `versionId`; для OEM — `CREATION_DATE`). Хранение: `data/cache/<source_id>/<fetched_utc>_<sha8>.<ext>` (`data/cache/` уже в .gitignore). Отключение и заморозка — два флага в `SourceStatus`, управляются из интерфейса и из `config.toml` (`[sources.<id>] enabled=false`, `frozen=true`), результат — статус INSUFFICIENT по механизму, никогда ABSENT.

Ключи дедупликации (обязательны, Т1 «дубли сообщений»): GOES JSON — (satellite, energy, time_tag); Kp GFZ — (datetime, status) с приоритетом def над prov; DONKI события — (activityID, versionId); уведомления DONKI — messageID; SOCRATES — (NORAD_CAT_ID_1, NORAD_CAT_ID_2, TCA); OEM — CREATION_DATE; выпуски NGDC — строка `:Issued:`.

Измеренные объёмы и времена (curl, 18.09.2026): SOCRATES `sort-minRange.csv` 17 416 442 байта, 154 558 строк, 12,9 с, у МКС 3 строки, горизонт TCA 2026-09-17 22:00 — 2026-09-24 22:00 (7 суток), запуск 3 раза в сутки (текст страницы SOCRATES Plus); GOES 7-day JSON 1 695 035 байт, 0,4 с; GOES 3-day 724 863 байта; GFZ файл с 1932 года 5 504 038 байт, 1,0 с; NCEI GOES-18 SGPS L2 за 2024-05-10 2 621 659 байт, за 2026-09-17 420 830 байт; OEM NASA 2024-05-08 718 328 байт (5403 вектора); уведомления DONKI за 9–13 мая 2024 102 668 байт (61 сообщение).

Наблюдённый троттлинг: после двух загрузок 17-МБ CSV три следующих запроса к CelesTrak (`table-socrates.php`, `search.php`, `socrates-format.php`) завершились таймаутом 60 с (код 000); `pub/TLE/catalog.txt` — 403. Space-Track документирует лимит «менее 30 запросов в минуту и 300 в час». Следовательно: SOCRATES качать не чаще раза в 8 ч, через HEAD с If-Modified-Since, в фоне, с кешем; в интерфейсе показывать возраст кеша. Ошибки классифицировать: Timeout, HTTPError, Quota (429/403), ParseError, PartialResponse — все ведут к INSUFFICIENT/STALE с сообщением, ни одна — к «благоприятно» (Т6).
