# Устройство приложения: для специалиста по коду

Описывает то, что построено, а не то, что планировалось. Документ `docs/ARHITEKTURA.md` —
это план от 17.09 с распределением обязанностей и графиком; читать его как описание системы
нельзя, он устарел. Здесь — фактическая структура на момент сдачи.

Объём: 21 686 строк в `app/` и `vkd/`, 67 файлов проверок, 1 166 автоматических проверок.

---

## 1. Главный принцип: экран ничего не считает

Весь расчёт делает ОДНА функция — `app.compute.run(...)`. Она возвращает объект `Result`, внутри
которого лежит `S` — СНИМОК РАСЧЁТА, обычный словарь. Всё, что видно на экране, попадает в
отчёт и в архив выгрузки, берётся из этого снимка и только из него.

Отсюда три следствия, на которых держится проверяемость:

- экран нельзя обвинить в том, что он показал не то, что посчитано: он не умеет считать;
- отчёт и экран не могут разойтись: у них один источник;
- сохранённый снимок вместе с сырыми записями источников позволяет повторить расчёт без сети
  и сверить числа — этим занят `scripts/replay_all.py`, 11 примеров из 11.

```
источники ──► vkd/sources ──► vkd/integration ──┐
                                                ├──► app.compute.run ──► S (снимок) ──► app/ui, app/export
орбита    ──► vkd/orbit ────────────────────────┤
модели    ──► vkd/assess ───► vkd/windows ──────┘
```

## 2. Слои и кто за что отвечает

### `vkd/sources` — получение данных, свой слой кеша и квитанций

| файл | что делает |
|---|---|
| `live.py` | живые продукты: поток протонов GOES, индекс Kp GFZ, элементы орбиты, бюллетень NOAA |
| `live_cache.py` | получение с кешем, квитанцией на точные байты, паузой запросов и снимком репозитория как последним рубежом |
| `live_parsers.py`, `noaa.py`, `donki.py` | разбор форматов; `donki.parse_notification` разбирает уведомления NASA |
| `goes_archive.py`, `gfz_archive.py` | архив 2024 года |
| `registry.py`, `replay.py` | реестр источников и воспроизведение из сохранённых байтов |

Ключевое правило слоя: **у каждой записи есть свои байты и контрольная сумма**. Идентификатор,
который называет любой фактор на экране, обязан иметь эти байты в архиве выгрузки, иначе
повтор без сети не воспроизведёт число. Это проверяется `tests/test_closeout.py`.

### `vkd/orbit` — где находится станция

| файл | что делает |
|---|---|
| `trajectory.py` | распространение по двухстрочным элементам, построение трассы с шагом 1 мин |
| `magnetic.py` | поле IGRF вдоль трассы: модуль поля, координаты Мак-Илвейна, жёсткость обрезания |
| `cutoff_table.py` | таблица Ж.1 ОСТ 134-1044-2007 — основной путь для обрезания; диполь остался запасным |
| `states.py`, `oem.py` | инерциальные состояния EME2000; эфемериды NASA/JSC для исторического режима |
| `integration.py` | `integrate_time` — интеграл по фактическому времени с обрезкой по границам окна |

`integrate_time` — несущая функция всего расчёта: по ней считаются и минуты в аномалии, и
флюенс, и число попаданий. Перебор начал зовёт её же с другими границами, поэтому совпадение
перебора с пооконным расчётом верно по построению, а не проверяется каждый раз заново.

### `vkd/assess` — физические модели

| файл | модель | первоисточник |
|---|---|---|
| `trapped.py` | поток захваченных протонов | ОСТ 134-1044-2007, прил. А |
| `dose.py` | поглощённая доза за защитой скафандра | тот же ОСТ, прил. К |
| `meteoroids.py` | средний фон метеороидов | ECSS-E-ST-10-04C, формула 10-1 |
| `seasonal.py` | 49 метеорных потоков конкретной даты | ECSS-E-ST-10-04C, табл. C-2 |
| `debris.py` | техногенное вещество | ГОСТ Р 25645.167-2005 |
| `magcoords.py` | координаты для таблиц ОСТ | эксцентричный диполь Fraser-Smith |
| `magcheck.py` | НЕЗАВИСИМАЯ проверка координат трассировкой силовой линии | ОСТ, прил. Д; в рабочий путь не подключён |
| `cutoff.py` | отсечка по времени публикации | правило проекта |

Каждый модуль отдаёт вместе со значением строку правила и строку ограничений по-русски. Эти
строки идут на экран дословно — текст модели живёт рядом с моделью, а не в слое экрана.

### `vkd/windows` — оценка и выбор

| файл | что делает |
|---|---|
| `compare.py` | оценка окна: собирает механизмы из факторов; правило вердикта, пять исходов |
| `scan.py` | перебор всех начал на сроке; ранжирование по правилу доминирования |
| `sensitivity.py` | устойчивость выбора на сетке порогов 3×3 |
| `scenario.py` | сценарии «что если» |
| `outlook.py` | перспектива до 27 суток с объявленными ярусами точности |

`assess_window` возвращает `WindowAssessment` с механизмами; каждый механизм несёт факторы,
покрытие, условия проверки и заметки. `recommend` применяет правило из пяти шагов и
возвращает исход вместе с объявленной областью вывода.

### `vkd/integration` — мосты области Б к источникам

`orbit_bridge.py`, `noaa_forecast.py`, `noaa_27day.py`, `donki_live.py` — каждый берёт сырой
продукт через общий слой получения и приводит к типам проекта. Мосты нужны потому, что
`vkd/sources` принадлежит второму исполнителю: правки делаются здесь, не в его области.

### `vkd/explain` — объяснения

`cards.py` строит карточку предупреждения по семи пунктам постановки. `format.py` — форматирование.

### `app` — экран, выгрузка, рисунки

| файл | что делает |
|---|---|
| `compute.py` | ЕДИНСТВЕННОЕ место расчёта; собирает снимок `S` |
| `main.py` | порядок блоков экрана, вкладки, ввод |
| `ui.py` | оформление, форматирование величин, тексты правил, блок вердикта, таблица формул |
| `viz.py`, `obs.py` | рисунки Plotly |
| `globe.py` | трёхмерный глобус как встроенный документ, three.js |
| `backdrop.py` | фон со звёздами, проверка контраста |
| `export.py` | архив выгрузки: отчёт, запрос, факторы, сырые записи, манифест |
| `report_pdf.py` | PDF-отчёт; библиотека не входит в зависимости площадки, при её отсутствии в архив кладётся причина |
| `fetch_guard.py` | общий предел времени на получение живых источников |
| `norms.py` | нормы как контекст |

## 3. Снимок расчёта: что лежит в `S`

Верхний уровень: `request`, `computed_utc`, `mode`, `windows`, `recommendation`, `scan`,
`cards`, `coverage_map`, `coverage_declared`, `forecasts`, `observations`, `meteoroids`,
`robustness`, `history`, `source_versions`, `raw_records`, `effective_config`,
`algorithm_version`, `schema_version`, `git_commit`.

Два ключа несут проверяемость:

- `source_versions` — по каждой записи контрольная сумма, время публикации и доказательство
  доступности;
- `raw_records` — сами байты в base64; по ним повтор считает заново без сети.

Форма ключа `scan` зафиксирована как договор между расчётом и экраном; описана в
`docs/design/TZ_ROUND11.md`, раздел 1a.

## 4. Настройки

Всё вне кода: `config/settings.toml`. Пороги аномалии, энергия канала, допуски равнозначности,
предельный возраст элементов орбиты, шаг перебора, сроки ожидания источников и общий предел
получения. Переменная `VKD_SETTINGS` позволяет подменить файл целиком.

## 5. Как запустить и как проверить

```
pip install -r requirements.txt
streamlit run streamlit_app.py
python -m pytest -q            # 1166 проверок, около 19 минут, сеть не нужна
python scripts/replay_all.py   # 11 из 11 сохранённых расчётов воспроизводятся
```

Точка входа `streamlit_app.py` — тонкая обёртка над `app/main.py`.

## 6. Правила, которые объясняют странные на вид места в коде

1. **Нет данных — говорим прямо, а не подставляем ноль.** Отсутствие расчёта и нулевой риск —
   разные утверждения, и код нигде их не смешивает.
2. **Каждое число прослеживается до записи.** Отсюда идентификаторы записей в каждом факторе и
   проверка, что их байты лежат в архиве.
3. **Суточные вероятности не пересчитываются в вероятность за окно** ни при каких условиях.
4. **`CONTRACT.md` правит только человек.** Расхождения кода и договора записываются в журнал,
   а не заглаживаются.
5. **Кодировка и переводы строк объявляются явно.** Чтение файла без указания кодировки и
   виндовые переводы строк в хешируемых данных дважды за сутки ломали проверки на Windows при
   исправном коде.
