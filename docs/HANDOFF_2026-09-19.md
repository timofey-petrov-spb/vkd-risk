## 3. Тонкие места, где легко сломать физику или честность

1. `cutoff` применяется к каждой записи отдельно (`vkd/assess/cutoff.py`): `published_utc ≤ cutoff` и `t_utc ≤ cutoff` для наблюдений; прогнозы могут иметь `t_utc` в будущем (R6). Вложенные Kp карточек GST без публикации — только в разбор после факта. Любая «оптимизация» здесь = утечка будущего = Т4 в ноль.
2. Суточные вероятности NOAA (S1+, протонное событие) **не пересчитываются** в вероятность за окно. Прогноз Kp NOAA — 3-часовые ячейки как есть. Это требование A2 (`vkd/history/README.md`).
3. Метеороиды: одна модель Grün, случайно кувыркающаяся пластина 1 м², m ≥ 10⁻³ г, по фактической высоте трассы, интеграл по dt, концы окна включены. Потоки конкретной даты и техногенный мусор **не** включены и объявлены. Различие окон по этой линии ~0,01 % — её роль охват и абсолютная оценка, не выбор окна.
4. Ни одного слова «безопасно». Вердикты только: предпочтительно / компромисс / равнозначны / все требуют проверки / оснований недостаточно. Условия — «правило команды, не норма».
5. Единицы: флюенс — част./см² (всенаправленный, ср уже проинтегрирован в таблицах ОСТ — R3); Kp безразмерен; GOES — pfu = част./(см²·с·ср) ≥10 МэВ.
6. Примеры `examples/` пересобираются `scripts/make_examples.py` и должны воспроизводиться `scripts/replay_example.py` (исторические — детерминированно без TLE). Меняешь модель → пересобирай примеры и обновляй числа в `docs/EKSPERIMENTY*.md`.

## 9. Целевой образ экрана — бриф пользователя (19.09, слова владельца)

«Абсолютно понятные интуитивные графики, если они нужны; абсолютно понятное управление; приложение выглядит достойным,
академически верным решателем; всё аргументировано, без заглушек, чётко и ясно; глядя на приложение, всё становится ясно».
Принцип: просто, понятно, прозрачно, точно, ничего лишнего. Ниже — как это проверять.

1. **Три вопроса в этом порядке**, сверху вниз, без прокрутки на ноутбуке: «Когда выходить?» (вердикт и окно), «Почему?»
   (две-три величины с единицами и происхождением), «Откуда это известно?» (источник, время публикации, ссылка на запись).
   Всё остальное — на один клик глубже (вкладки), не на главном экране.
2. **Каждое число** несёт единицу, происхождение (наблюдение / внешний прогноз / наш расчёт), момент данных и путь к записи.
   Нет числа без единицы; нет модели без ссылки на стандарт (ОСТ 134-1044-2007 прил. А, ECSS-E-ST-10-04C формула 10-1 и Table J-6,
   Fraser-Smith 1987, шкалы NOAA SWPC, правило CONTRACT §4).
3. **Графиков на главном экране не больше двух.** (а) Лента окна: ось времени UTC; сверху экспозиция по трассе (пролёты аномалии
   полосами, |B| линией), снизу условия (наблюдения и прогнозы, события маркерами). Заголовок графика говорит, ЧТО показано и ОТКУДА
   («Поле на трассе МКС по IGRF — наш расчёт»), оси подписаны с единицами, легенда не длиннее четырёх строк, цвета закреплены:
   синий — наш расчёт, зелёный — наблюдение, янтарный — внешний прогноз, красный — условие/аномалия. Логарифмическая ось только
   с явными метками 0,1/1/10/100/1000. Панель инструментов plotly скрыта. (б) Сравнение окон — компактная таблица величин, не
   столбчатый график с двумя осями.
4. **Управление**: боковая панель из четырёх групп с простыми подписями — Режим; Когда (дата, час); Окно работ (длительность,
   сдвиги); Источники (только в текущем режиме). Всё специальное — в свёртке «Настройки специалиста». У каждого элемента
