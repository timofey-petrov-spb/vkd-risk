## Что соединено

- История вызывается с `Request`: длительность, горизонт, отсечка, задержка. Численный GOES iSWA используется в разборе; в строгий прогноз ряд с недоказанной публикацией не допускается. Проверка факта после отсечки получает отдельный retrospective bundle.
- GOES оценивается по фактическим 5-минутным ячейкам каждого окна, по максимуму средних; пропуски не заполняются. Условие по текущему наблюдению не переносится на далёкое окно. Порог по каналу >100 МэВ не превращается в уровень S по >10 МэВ.
- Задержка сдвигает начало орбиты, сохраняет горизонт до 32 ч и исходную отсечку. Все варианты моста отдают пакет r/v EME2000. Один TLE с разными квитанциями не перезаписывает сессии: ключ включает квитанцию, записи атомарны.
- ZIP содержит настоящий `source_id → raw_record_id → metadata`, хеши, точные исходные байты, карту покрытия и отображение ID на имена файлов. Добавлены доказательства орбитальных и модельных входов. Сценарные записи помечены как синтетические. Код модели в доказательствах — реализация/константы, не наблюдение провайдера.
- Replay восстанавливает A4 GOES/Kp из байтов без сети, проверяет хеши реестра, сравнивает также значения и покрытие всех факторов. Отсутствующие входы воспроизводятся как отсутствующие. Исторический пересчёт использует версионированный архив репозитория; автономный ZIP без checkout проекта не обещается.
- В UI состояния источников передаются без преобразования строки `off` в булево значение. Численный GOES показан в разборе. Сценарные настройки отключаются с пояснением в строгом режиме.

## Изменения научного поведения — учитывать при приёмке

> **Приписка интегратора 19.09 (вечер), после приёмки восьмого круга.** Документ — передача А,
> его текст не переписан. Пункт 1 ниже действовал в версии `0.7.0` и **отменён решением
> владельца 19.09** (второй вариант самого А — «чёткое ограничение результата»): рекомендацию
> блокирует только ОТСУТСТВИЕ покрытия обязательной линии, частичное покрытие объявляется
> областью вывода рядом с вердиктом. Поэтому «реальные примеры могут иметь `insufficient`
> во всех режимах» на принятой сборке `0.8.0` больше не так: из десяти сохранённых примеров
> отказов три, и все три — по каналу с нулевым покрытием. Остальные пункты 2–5 в силе.
> Подробности — `docs/PROGRESS.md`, раздел 1д.

1. Неполное обязательное покрытие блокирует рекомендацию (CONTRACT §4.1); 95% точек больше не подписываются как полное покрытие. Сравнение факторов и предупреждения остаются. Реальные примеры могут иметь `insufficient` во всех режимах — это недостаточность модели/данных, а не ошибка запуска.
2. Эксцентричный диполь получает WGS84 ECEF из геодезических координат. Независимая проверка использует аналитическую формулу эллипсоида. Сам эксцентричный диполь по-прежнему приближение, не валидированная трассировка силовой линии.
3. `B/B0 < 1` даёт отсутствие модельного значения (`inconsistent_BB0`), а не молчаливый clamp к 1. За пределами модели нет нулевого риска; покрытие флюенса считается по всем точкам окна.
4. Средний Grün сохранён в исходных единицах и геометрии. Пока сезонный вклад не реализован и не проверен, обязательная линия метеороидов имеет частичное покрытие. Календарь потоков не заменяет численную сезонную модель.
5. DONKI-уведомление о WSA-ENLIL подписывается как уведомление с опубликованным диапазоном; верхняя граница диапазона не называется `kp_90`.
