# A3 → B2: инерциальные положения и скорости для сезонных метеороидов

Версия орбитального алгоритма `orbit-a3-v2`, расширения provenance —
`orbit-inertial-states-1`. Общие типы **2.1 неизменны**. Ветка
`codex/a3-inertial-states` построена поверх передачи GOES `adb99cf` и включает
её; принятый main при разработке — `6224156`. Реализация оценщика остаётся у Б.

## Вызов без второго расчёта орбиты

```python
from datetime import timedelta
from vkd.orbit import trajectory_with_provenance
from vkd.sources.registry import utc

start = request.eva_start_utc + timedelta(minutes=request.work_delay_min)
minutes = request.search_period_min + request.duration_min
meta, points, provenance = trajectory_with_provenance(
    start, minutes, 24000,  # фактический настроенный порог поля передать вместо примера
    mode=request.mode,
    cutoff_utc=request.cutoff_utc,
    step_seconds=60,
    include_inertial_states=True,
)
states = provenance['inertial_states']
times_utc = [utc(row['t_utc']) for row in states['samples']]
positions_km = [row['position_km'] for row in states['samples']]
velocities_km_s = [row['velocity_km_s'] for row in states['samples']]
```

Это пример прямого исторического вызова. В текущем режиме Б сохраняет
существующий `repo_root` с проверенным TLE/receipt из `stage_live_root`,
`max_tle_age_days` и актуальную отсечку расчёта. Не заменять его случайным
`tle_path` без метаданных. В `build_orbit` добавить флаг к каждому фактическому
вызову A3: live, строгая история, явно объявленная реконструкция.

`points[i]` и `states['samples'][i]` относятся к **одному времени и одному
решению орбиты**. Состояния берутся до геодезического преобразования и не
получаются дифференцированием широты/долготы. Пересчитывать орбиту отдельно
для каждого механизма не нужно. Порог поля не изменяет r/v.

## Смысл полей

| Поле | Значение |
|---|---|
| `frame`, `axes` | EME2000: средний экватор и равноденствие J2000 |
| `center` | центр Земли |
| `time_system`, `t_utc` | UTC; сериализованные строки ISO-8601 с Z |
| `position_km` | три компоненты радиус-вектора, км |
| `velocity_km_s` | три компоненты геоцентрической инерциальной скорости, км/с |
| `raw_record_id`, `segment_index` | исходная запись и сегмент каждой точки |
| `segments[*].input_frame` | TEME для TLE или EME2000 для OEM |
| `segments[*].output_frame` | EME2000 для всех переданных векторов |
| `source_hashes` | SHA исходных орбитальных записей; сами записи — в `provenance.records` |
| `is_reconstruction` | тот же статус доказанности исходных данных, что у орбитального решения |
| `software`, `timescale_tables_sha256` | версии библиотек и хеш встроенных таблиц времени |
| `content_sha256` | SHA канонического JSON всего блока без самого поля хеша |

Старое `TrajectoryMeta.frame` описывает **исходную** систему и сохранено
ради совместимости: для SGP4 оно остаётся TEME. Для сезонных векторов
читать `states.frame`, не подставлять туда `meta.frame`.
Величины в массиве r/v не вращаются вместе с Землёй.

OEM: берутся исходные EME2000 и аналитическая производная кубической
интерполяции Эрмита. TLE: SGP4/TEME → Skyfield/GCRS → постоянный поворот
IERS-2003 к J2000. [Skyfield](https://rhodesmill.org/skyfield/api-position.html)
определяет оси своих геоцентрических r/v; [описание TEME](https://rhodesmill.org/skyfield/api-framelib.html)
отделяет его от неподвижных осей. Скорость SGP4 использует принятую Skyfield
мгновенную матрицу без малого члена скорости прецессии/нутации осей;
субмиллиметровая точность скорости физической орбиты не заявлена.

## Интеграционные правила

1. Сдвиг работ применить к началу **обеих** траекторий; горизонт до конца
   последнего окна — до 32 ч от сдвинутого начала. Историческая отсечка
   остаётся исходной. Не сдвигать окна после расчёта более короткой трассы.
2. Векторы радиантов и скорости метеороидов должны быть в той же системе
   EME2000/J2000 и геоцентрическом соглашении. Конвенция каталога A5 остаётся
   инженерным допущением; r/v станции не доказывают эпоху радианта.
3. Для относительной скорости использовать `v_meteoroid - v_station`.
   Не вычитать земную вращательную скорость ещё раз и не применять
   барицентрическую скорость Земли. Геометрическая тень определяется
   геоцентрическим направлением прихода, не относительной скоростью мишени.
4. В `history_forecast` неизвестная историческая публикация OEM по-прежнему
   вызывает `OrbitDataError`. Мост Б может отдельно предложить объявленную
   реконструкцию; состояние не превращается от этого в строгий прогноз.
5. Сохранять весь блок состояний в едином снимке/выгрузке, а хеш, систему,
   версию и ограничения — в компактном отчёте. Текущий
   `provenance_summary()` его пока не переносит. При повторе проверять
   исходные записи и хеш блока; для OEM закреплять `oem_raw_record_id`.
6. Концы сетки включены. Последний шаг может быть короче; интегрировать
   реальные dt. Границы окон должны присутствовать явно. Нельзя добавлять
   последнюю точку как лишнюю минуту экспозиции.
7. Полнота r/v не повышает сезонную оценку автоматически до FULL. Ограничения
   [A5](../methods/METEOROIDS_SEASONAL_SPEC.md) и чувствительность сохраняются.

## Приёмка и связь с критериями

- **Т2:** исходные узлы NASA OEM для r/v, независимая ERFA-проверка шести
  преобразований TEME→J2000 на горизонте 32 ч. Допуски компонентов — 1 см
  и 0,01 мм/с; фактические векторные расхождения меньше 0,2 мм и 0,00022 мм/с.
  Это проверка преобразования при одинаковых входах UT1/SGP4, не точность
  предсказания станции. Нативный SGP4 отдельно проверяется эталонами Vallado.
- **Т3:** проверка производной Эрмита независимой аналитической формулой;
  единицы и системы одинаковы для всех r/v. Физический оценщик не дублирован.
- **Т4/Т6:** строгая история не получает скрытого резерва; устаревание/хеши
  источников проверяются; пропуск OEM между узлами выходной сетки вызывает
  отказ даже при шаге 600 с. Это усилено и для прежнего вызова без r/v.
- **Т7/Т8:** прежний вызов без флага даёт те же точки, нет новых runtime-
  зависимостей; JSON, версии, хеши и пример для второго участника сохранены.

Команды: `python -m pytest tests/orbit -q` и
`python tests/sources/run_pinned_suite.py`.
Пример: `data/orbit/inertial_states_example.json`.
Численный отчёт: `data/orbit/inertial_states_verification.json`.
Эталон и генератор: `tests/orbit/fixtures/inertial_reference.json`,
`build_inertial_reference.py`; pyerfa нужен только для перегенерации эталона.
