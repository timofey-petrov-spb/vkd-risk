# A2 v4: сверка с main d674dba и восстановление GFZ

Ветка `codex/a2-integration-hardening` объединяет `origin/main d674dba` и
предыдущую передачу А `66a2470` (включая GOES/A4/A5). Это накопительная
передача: предыдущие PR не нужно переносить повторными cherry-pick.
Типы 2.2 прочитаны, **согласовано**: добавления Condition/coverage_notes
обратно совместимы с данными А. CONTRACT и файлы Б вручную не редактировались.

## Что исправлено А

Временный адаптер Б включал окончательный GFZ Kp, а прежний адаптер А —
только датированные уведомления. При автоматическом выборе `vkd.history`
терялся непрерывный ряд разбора. Добавлен проверяемый архив `data/gfz_2024/`
и `vkd/sources/gfz_archive.py`: 488 ячеек, три часа каждая, 61 день;
исходные байты, SHA, версия и качество по D. 24 значения и начала интервалов
сверены с отдельным ответом официального JSON API GFZ. Общее происхождение
данных сохраняется: это проверка двух форматов, не независимая физическая валидация.

`history_bundle()` без аргументов теперь выдаёт 21 наблюдение из уведомлений
и 488 ячеек GFZ, 166 событий. У GFZ `published_utc=None`, поэтому обычный
`apply_cutoff` исключает их из строгого режима. Датированные наблюдения DONKI
не удалены: их нельзя объявлять отсутствующими только потому, что GFZ исключён.
В разборе при равном времени `max(..., key=t_utc)` получает сначала GFZ.
Каждая ячейка ссылается на один байтовый выпуск по хешу; её положение определяется
valid_from/to, а не искусственным отдельным «выпуском» на каждое наблюдение.

`history_snapshot(request)` выдаёт отдельное покрытие GFZ и объединение
интервалов наблюдений Kp. Контекст 48 ч не завышает покрытие окна; за концом
архива нет экстраполяции. Схема берётся из актуального SCHEMA_VERSION (2.2).

## Приоритет подключения — перед новыми возможностями

1. Исправить Fetch/replay, адаптировать проверку реального поставщика; общий
   набор должен стать зелёным без сокрытия неправильных смысловых утверждений.
2. Передать реальный Request в `history_bundle`/`history_snapshot`, включая
   work_delay и исходный cutoff. GOES уже есть у А, но текущий no-arg вызов
   приложения его намеренно не получает. Для панели «после отсечки» нужен
   отдельный review-снимок, который не подмешивается в оценку прогноза.
3. Сохранить `_history.source_versions` и покрытие в настоящем реестре
   manifest. Сейчас `app/export.py` записывает `source_versions=S['sources']`:
   это панель статусов, не согласованный source_id→raw_record_id→metadata.
   Наличие raw внутри ZIP не заменяет правильную структуру реестра.
4. Подключить r/v A3 по `A3_STATES_HANDOFF.md`, задержку применить к орбите,
   а не только окнам; реализовать сезонный оценщик в зоне Б по спецификации А5.
5. Пересобрать примеры на новом коде; повторить 3 режима, отключение/кеш,
   поздние данные, 32 ч и ZIP replay на одном SHA; затем обновить PROGRESS.

## Ответы по открытым решениям

- R9: согласовано как политика проверки, прогноз Kp с исходным трёхчасовым
  сроком действия, без превращения суточной вероятности в событие внутри окна.
- Р-О1: согласована отдельно подписанная реконструкция; это не доказанная
  доступность орбиты в прошлом и не основание объявить весь результат строгим.
- Р-О2: согласовано, никакой подмены недоступной орбиты заглушкой.
- R10: не подтверждаю публикацию mutable enlilList по времени завершения
  прогона. `max(completion, submission)+60 мин` уменьшает часть утечки,
  но не доказывает доступность конкретной редакции. Датированные исходные
  уведомления А2 остаются основой строгой линии. kp_90 — сценарий угла IMF,
  не доказанный медианный прогноз; прежнее обоснование/источники — journal/friend.md.
- R11: только объявленное приближение, не численная валидация McIlwain L.
  В актуальном `vkd/assess/magcoords.py` всё ещё сферическое преобразование
  геодезической широты/высоты. Нужен WGS84 ECEF до вычитания смещения диполя;
  cutoff_GV от прежнего центрального диполя нельзя подписывать новым методом.
- R12: степенная интерполяция/интеграл между узлами и отсечение хвоста допустимы
  как явно объявленный численный метод; единицы всенаправленного флюенса —
  част./см². «Минуты доступности не реализованы» — честное описание ограничения,
  но не закрытие обещанной функции. CONTRACT редактирует только человек.

Средний Grün без проверенных сезонных потоков остаётся частичным охватом.
Наличие приложения, успешного replay или ненулевого флюенса не доказывает
закрытие всех критериев. Следующий шаг А после интеграции Б — перепроверить
стык, покрытия/экспорт и чувствительность орбиты к шагу на том же SHA.
