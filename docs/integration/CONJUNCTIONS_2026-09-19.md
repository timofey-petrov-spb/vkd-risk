# A6: собственный расчёт сближений — передача Б

База `db94f1b`, ветка `codex/a6-conjunction-screening`. Типы `vkd/types.py`,

Готовый вычислительный модуль и снимок передаются для подключения Б.

## Что подключать

```python
from datetime import timedelta
from vkd.sources.catalogue import catalogue_latest, primary_catalogue_from_fetch
from vkd.conjunctions import screen_catalogue, assess_window
from vkd.conjunctions.snapshot import load_config, source_records

catalogues = []
acquisition_statuses = []
for selection in ('active', 'debris', 'rocket_bodies'):
    c, fetch = catalogue_latest(selection, disabled=False, cache_dir=shared_cache)
    acquisition_statuses.append(fetch)  # показать отказ даже при успешных остальных
    if c is not None:
        catalogues.append(c)

# tle_fetch — ТОТ ЖЕ Fetch A4, из которого основная траектория получила TLE.
# Не делать повторный tle_latest(). Иначе каталожная МКС может иметь иную эпоху.
primary_catalogue = primary_catalogue_from_fetch(tle_fetch)
catalogues.append(primary_catalogue)
screen = screen_catalogue(
    tuple(catalogues), request.eva_start_utc,
    request.eva_start_utc + timedelta(
        minutes=request.search_period_min + request.duration_min),
    primary=primary_catalogue.objects[0], decision_utc=calculation_cutoff,
    config=load_config(),
)
mechanism = assess_window(screen, window)  # vkd.types.MechanismAssessment
details = screen.to_dict()                # одна JSON-ready версия для UI и ZIP
raw = source_records(catalogues)          # существующий формат A4 content_base64
```

`screen_catalogue` — чистый расчёт без сети; `Catalogue` и `GPObject` — внутренние
входы каталожного адаптера, не замена замороженных типов. На выходе события
используют `vkd.types.Conjunction`, оценки окон — существующие типы Б.
`primary_catalogue_from_fetch` принимает и TLE-текст, и исходный JSON TLE A4.

**Критично: не передавать просто `screen.conjunctions` в старый `compare.py`.**
Там все события подписаны `EXTERNAL_FORECAST/SOCRATES`, любое расстояние создаёт
условие, пустой список означает отсутствие данных, а непустой — FULL.
Нужна замена третьего механизма результатом `assess_window(screen, win)`.
`mechanism.conditions` / `needs_check_reasons` добавлять в общие условия окна
и в фильтрацию кандидатов перебора **одинаково**, без двойного учёта старого CONJ.
Для автоматического поиска A6 считать один раз на весь горизонт; для каждого
окна вызвать только дешёвый `assess_window`. Новых запросов/SGP4 на окно нет.

Для UI и отчёта:

- перечень `screen.encounters`: `conjunction.tca_utc`, `miss_distance_km`,
  `relative_speed_km_s`, ID и имя, эпохи **обоих** объектов, их подписанная давность
  в сутки относительно TCA; отрицательная давность — время до эпохи элементов;
- `at_horizon_boundary=True` — ограниченный минимум на краю горизонта,
  истинный локальный TCA может лежать вне расчёта; не скрывать эту отметку;
- `screen.stats`: входные/уникальные объекты, допустимые по давности, после
  каждого сита, уточнённые интервалы, найденные объекты/события, время;
- `stats.shared_primary_elements`: объекты с **тождественными** GP станции,
  исключённые из независимых сближений. Это не определение статуса стыковки;
- `stats.excluded`, `provenance.input_audit`, `limitations_ru`: пропуски с причиной;
- манифесту передать `provenance.catalogues`, конфигурацию, версию метода,
  сведения о первичной орбите и исходные записи через `source_records`.

Поля `Conjunction.max_probability=None`, `published_utc=None` намеренно:
своему расчёту не выдумывается время публикации. `run_utc` — время вычисления,
`provenance.decision_utc` — отсечка доступных исходников, это разные времена.
Происхождение оценки — `OWN_CALCULATION`. Старый отсекатель внешних сообщений
не применять к этим собственным результатам: исходники уже отобраны до расчёта.

## Политика и границы

Настройки — `config/conjunctions.toml`, все попадают в снимок. По умолчанию:
выдавать минимумы ≤50 км, предупреждать при промахе **<5 км** и TCA внутри
полуоткрытого окна `[начало, конец)`. Оба расстояния — правила прототипа,
не нормы эксплуатации. Ровно 5 км не даёт предупреждения при такой формулировке.
Длительность горизонта поддержана до 72 ч, но элементы должны оставаться в
пределах 3 суток от эпохи **до его конца**. Поэтому 72-часовой запрос со старыми
элементами может быть недоступен. Не повышать этот предел молча ради ответа.

Пригодность снимка каталога — до 24 ч от его получения; запросы к каждому
источнику — не чаще раза в два часа, включая ошибки и force_refresh.
Режимы A4 on/cache/off сохранены; выключение одной сессии не стирает общий кеш.
Сетевой отказ при пригодном кеше сохраняет данные с отметкой; без данных — NONE.

**Современный каталог не подставляется в 2024.** Для истории передавать настоящую
историческую отсечку, современный receipt будет исключён. Датированного каталога
2024 в этой поставке нет; линия там не покрыта. Нельзя назвать снимок современного
каталога «историческим» только из-за старой эпохи одной строки.

Получены три CelesTrak GP CSV-выборки: `GROUP=active`, `NAME=DEB`, `NAME=R/B`.
Это **не полный публичный каталог**: например, некоторые неработающие целые
аппараты сюда не входят. Неизвестно и число отсутствующих объектов. Выборка
охватывает аппараты, обломки и корпуса; её состав объявлен, ограничения сохранены.
Шестизначные NORAD поддерживаются: обычный TLE их теряет.
Даже успешная проверка выборки даёт `Coverage.PARTIAL`, никогда FULL.
Ноль событий при успешно проверенной выборке отличается от `None` при отсутствии
пригодных данных. Флаг `selection_calculation_complete` относится только к численной
обработке выбранных записей, не к полноте опасностей в космосе.

## Численная схема

1. Средние перигей/апогей вторичного объекта против диапазона радиусов станции.
   Запас — 100 км + радиус выдачи. Сито не отбрасывает объекты при перигее ниже
   300 км, |BSTAR|≥0,001 или давности в начале ≥1 суток: сопротивление/устаревание
   делают такой отсев ненадёжным. Пропагатор и константы — SGP4/WGS72.
2. Векторизованный SGP4 блоками по 128 объектов, TEME у **обоих** участников,
   шаг ≤60 с. Проверяется расстояние до всей относительной хорды между узлами,
   с запасом `a_rel*dt²/8`; `a_rel=0,04 км/с²`. Это превышает двойное ускорение
   тяготения у поверхности Земли (~0,0196 км/с²), но не ограничивает неизвестные
   ошибки GP или манёвры. Условие применимости — внешняя земная орбита без манёвра.
3. У прошедших промежутков сетка ≤5 с выделяет смену подхода на удаление;
   решается `r_relative·v_relative=0` с допуском 0,001 с. Дубли на стыках убираются.
   В отчёте сохраняются и минимумы на краях горизонта. Элементы, ошибки SGP4
   и положения внутри Земли не превращаются в нулевое расстояние/нулевой риск.

Сетка 60 с сама по себе может пропустить пролёт: при относительной скорости
15 км/с объект способен пройти 900 км за минуту. На это есть отдельный тест.
Проверка «дистанция в узлах меньше 50 км» здесь не используется.

## Первоисточники и честность физики

- [CelesTrak: GP formats](https://celestrak.org/NORAD/documentation/gp-data-formats.php):
  GP CSV/OMM, TEME/UTC/SGP4 и ограничения TLE.
- [CelesTrak: текущие данные](https://celestrak.org/NORAD/elements/),
  [правила использования](https://celestrak.org/usage-policy.php).
- [NASA CARA: оценка сближения](https://www.nasa.gov/cara/step-2-close-approach-risk-assessment/),
  [NASA Spacecraft Conjunction Assessment and Collision Avoidance Best Practices Handbook](https://ntrs.nasa.gov/citations/20230002470):
  дистанция сама по себе не является оценкой вероятности столкновения;
  общедоступные GP не обеспечивают необходимую для неё ковариацию.

**Нет независимой наблюдательной валидации истинных промахов, нет Pc и нет гарантии
выявить все реальные угрозы.** Доступны собственная геометрическая оценка,
численные проверки, происхождение и явно ограниченная область результата.
