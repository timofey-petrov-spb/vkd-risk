# Передача A1/A2 + A4 + A5, база main 6224156

Ветка `codex/a1-goes-history` включает предыдущую передачу
`codex/a4-live-sources` (369bc03), затем main 6224156 и новый блок.
Интегрировать эту ветку целиком; отдельный повторный cherry-pick прежнего
A2/A4 не нужен. Main, типы, CONTRACT, оценщики и интерфейс вручную не менялись.

## Что реализовано

1. **A1 GOES:** 65 исходных суточных ответов NASA iSWA, 29.04–02.07,
   18 400 пригодных численных наблюдений ≥10 МэВ, pfu; схема, SHA-256,
   версия каждого выпуска, URL и время получения. Охват мая–июня 98,3436%,
   реальные разрывы сохранены. [Данные и инструкция](../../data/goes_2024/README.md).
2. **A2 v3:** `history_snapshot(request)` и `history_bundle(request)`
   используют GOES в разборе. Строгий режим исключает неизвестную публикацию.
   Никаких запросов в сеть, замены пропусков или повышения качества данных.
3. **A4 v2:** совместимость с новым конфигом Б: `False/on`, `True/cache`,
   `'off'`; список TLE-адресов, оба JSON-формата, точные исходные bytes,
   отдельный хеш извлечённого TLE, фактический `Fetch.url`, независимые кеши.
   Два разных CelesTrak URL не обходят общий двухчасовой интервал запросов.
4. **A5:** [сезонная спецификация](../methods/METEOROIDS_SEASONAL_SPEC.md),
   49 арифметических контролей, геометрия/скорость/затенение и шесть
   солнечных дат. Б может начать инженерную версию по §0. Не объявлять
   `FULL`: нормировка табличного k, координатная эпоха и двухкомпонентные
   профили ещё имеют явно записанные допущения.

## Точный стык GOES для Б

Общие типы остаются **2.1**. Вызов должен получать **реальный Request**:

```python
snapshot = history_snapshot(request)
samples = snapshot['samples']
events = snapshot['events']
source_versions = snapshot['source_versions']
raw_records = snapshot['raw_records']
coverage_map = snapshot['coverage_map']
```

Либо прежний tuple `history_bundle(request)`: аудит/реестр/покрытие находятся
в `raw['_history']`. Без аргумента намеренно остаётся только DONKI-каталог:
угадывать режим, отсечку и выбранное окно нельзя.

`source_id='nasa_iswa_goes_primary_p5m'`,
`channel_id='goes_p_ge10MeV'`, `kind=observation`, `unit='pfu'`,
`quality='unknown'`, `published_utc=None`. `valid_from/to` — действительные
границы пятиминутного усреднения, не прогнозная протяжённость риска.
Отдельная запись схемы HAPI также передаётся в реестре и raw.

Снимок содержит 48 ч контекста и весь горизонт окна/поиска с задержкой.
Для оценки отдельного окна Б отбирает пересекающиеся интервалы и считает
**его** покрытие; нельзя применить максимум из предшествующих 48 ч к
каждому будущему окну, протянуть последнюю точку через пробел или заменить
весь ряд одним значением. `coverage_map['goes_p_ge10MeV:observations']`
относится ко всему запрошенному горизонту, а не к любому его подокну.
Точечные сообщения о SEP не заменяют пробелы численного ряда.

`full` у этого канала означает полный **временной** охват числами.
Отсутствие инструментальных DQF остаётся ограничением; сама эта метка не
разрешает общую рекомендацию. В `history_forecast` покрытие GOES остаётся
`missing`, причина — недоказанная публикация версии; текущая выгрузка
не доказывает доступность в 2024 году.

## Конкретные изменения в области Б

- `app/compute.py:94–110`: получать архив после определения режима;
  передать Request вместо `history_bundle()`, убрать устаревшую ветку
  «архива GOES нет», сохранить ряд и его происхождение. Истории не нужна
  текущая сеть. Прежний [список стыков A2/A4](A2_A4_HANDOFF_2026-09-19.md)
  остаётся актуальным, в частности raw-аудит и вымышленные 24 ч событий.
- `app/main.py:122`: `_fetch_all(bool(disabled['goes']), bool(disabled['kp']))`
  теряет различие `'cache'`/`'off'`. Передавать исходные значения;
  в A4 `'off'` уже даёт полностью пустой Fetch без сети и чтения кеша.
  Позднее удаление только payload/raw_path в compute не очищает новые
  `Fetch.raw/metadata`; лучше не получать исключённый источник изначально.
- TLE: `Fetch.payload` — нормализованный текст, `Fetch.raw` — оригинальный
  HTTP-ответ, возможно JSON. У них закономерно разные хеши. В Manifest
  сохранить исходный receipt и `derived_tle`; не хешировать JSON как TLE.
  `celestrak_gp` пока совместимый логический ID продукта ISS TLE; реальный
  поставщик и выбранный адрес определяются URL, не именем этого ID.
- A5: оценщик пишет Б; для направленного расчёта понадобится массив
  инерциальных положений/скоростей из A3. Общие типы молча не расширять.
  Следующий шаг А — передача состояний с системой координат и происхождением.
