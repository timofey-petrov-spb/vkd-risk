# A6, второй приоритет: восстановление выпусков NOAA

Добавлено в общий реестр A1: **20 проверенных снимков оригинала NOAA 3-day**
из Internet Archive за 15 дат внутри разрыва 15.05–16.06.2024.
Провайдер прогноза — NOAA; место хранения копии — Wayback, не NASA и не NGDC.
Идентификатор источника: `noaa_wayback_3day_forecast`.

Скачаны 26 снимков с 18 дат. У шести распакованные байты HTTP-ответа
не совпали с SHA-1 payload digest из CDX. Причина может быть в транспортном
преобразовании архивного ответа; повреждение NOAA этим не доказано.
**Они исключены из строгой линии**, а не «починены» изменением хеша.
Список и причины: `data/source_registry_2024/noaa_wayback/rejected_captures.json`.

## Доказательство и отсечка

- Оригинальный CDX-ответ сохранён вместе с его SHA-256; для каждого принятого
  тела проверено точное совпадение base32(SHA-1(payload)) с digest из CDX.
- Наш SHA-256, оригинальные байты, URL конкретного `timestampid_` и время нашего
  скачивания сохранены. Git не меняет окончания строк сырых записей.
- `published_utc` — оригинальная строка `:Issued:`.
- `available_utc` — **время архивного снимка**, которое может быть позже Issued
  на часы. Приравнивать доступность этой редакции к более раннему Issued нельзя.
- `parse_forecast` проверяет digest/URL/времена; старый `replay_forecast` уже
  требует `published <= cutoff` и `available <= cutoff`.
- Поля Kp остаются трёхчасовыми, вероятности S1+ — суточными. Проза об уже
  наблюдавшихся явлениях не используется как прогноз.

Заодно исправлен реальный дефект парсера: текст обоснования может начинаться
`R1-R2 conditions ...`. Раньше это принималось за ещё одну числовую строку и
отклоняло весь корректный выпуск. Теперь для 3-day читаются именно таблицы
между заголовками дат и `Rationale:`. Все 117 прежних выпусков проходят прежние
проверки чисел без изменения результатов.

## Стык для Б — короткая правка его адаптера

Добавлен `vkd.history.forecast_tiers.replay_forecast_tiers` с теми же аргументами,
что `replay_forecast`. Полный NGDC имеет приоритет. Если полного покрытия нет,
выбирается своевременный выпуск с наибольшим покрытием из NGDC/Wayback;
при равенстве — более поздний Issued. Прогнозы разных выпусков не склеиваются.
Возвращаются обычные поля плюс `tier` и `tier_attempts`.

В **своём** `vkd/integration/noaa_forecast.py` Б может:

1. Заменить локальный импорт `replay_forecast` на
   `from vkd.history.forecast_tiers import replay_forecast_tiers as replay_forecast`.
2. После выбора `r` получить `actual_source = r['source_id']` и использовать его
   в `EnvironmentSample.source_id`, `raw[...]['source_id']`, `ForecastLine.source_id`.
   Не оставлять `src=noaa_ngdc_3day_forecast` для записи из Wayback.
3. Передавать в сырые записи также `available_utc`, `archive_timestamp`,
   `cdx_payload_digest`, `availability_evidence`; они уже в `r['record']`.
4. Сохранить `tier`/`tier_attempts` в снимке и назвать источник на экране
   «NOAA 3-day, архивная копия Wayback». Для недоступного горизонта показывать
   фактический последний выпуск; прежняя фиксированная фраза «весь разрыв NGDC
   не покрыт» после подключения будет слишком широкой.

Пока файлы интегратора не изменены: новые данные и API готовы, но приложение
само ещё не переключилось на резерв. Сближения переданы отдельным предыдущим
коммитом той же ветки. Перед финальной сдачей пересобрать примеры и повторить
эксперимент: дата 20 мая теперь имеет иной доступный прогноз.
