# ВКД-Риск

Документ сдачи для жюри. КосмоХакатон 2026, кейс «Прогнозирование внешних
рисков и планирование ВКД на МКС», 18–20 сентября 2026.
Веб-сервис на Python (Streamlit). Языковые модели в расчёте не применяются:
данные не текстовые.

Версия алгоритма в интерфейсе и выгрузке: `0.2.0-b2` (`app/main.py`,
`ALGO_VERSION`). Договор команды — `CONTRACT.md` v3.1; типы стыка —
`vkd/types.py` версии 2.1.

## 1. Что это и для кого

Сервис для аналитика ГОГУ (главной оперативной группы управления) при
подготовке выхода в открытый космос. Аналитик задаёт начало и длительность
ВКД и период поиска начала, а сервис получает орбиту МКС и открытые данные
о космической погоде, считает условия вдоль траектории по каждому механизму
воздействия отдельно, сравнивает два-три окна одинаковой длительности и
выдаёт рекомендацию либо явный отказ с видимым правилом, охватом и списком
недостающих данных. Это исследовательский прототип поддержки решений: допуск
к реальной ВКД остаётся за уполномоченными специалистами, и сервис его не
выдаёт.

Развёрнутое решение: `<ссылка появится после развёртывания>`.

## 2. Запуск за три команды

```
python -m pip install -r requirements.txt
python -m streamlit run app/main.py
python -m pytest
```

- Python 3.12–3.14. Проверено на 3.14.6 (Windows): 26 тестов проходят.
  `pyproject.toml` допускает `>=3.11`. Версии зависимостей закреплены точно
  в `requirements.txt` (numpy 2.5.1, pandas 2.3.3, scipy 1.18.0, sgp4 2.27,
  skyfield 1.55, ppigrf 2.1.0, requests 2.34.2, plotly 5.24.1,
  streamlit 1.64.0, python-dotenv 1.2.3, pytest 9.1.1).
- Ключи API не нужны. В коде нет обращений к переменным окружения,
  `.env` и `st.secrets`; `.gitignore` исключает `.env`,
  `.streamlit/secrets.toml` и `data/cache/`.
- Адрес сервиса печатает Streamlit в терминале (по умолчанию
  `http://localhost:8501`); `.streamlit/config.toml` задаёт `headless = true`,
  браузер сам не открывается.
- Что требует сети. В любом режиме при первой загрузке страницы сервис
  пробует живые запросы (таймаут 12 с на каждый, `experiments/stub_sources.py`):
  GOES `services.swpc.noaa.gov/json/goes/primary/integral-protons-3-day.json`,
  Kp `kp.gfz.de/app/json/` за последние двое суток,
  TLE `celestrak.org/NORAD/elements/gp.php?CATNR=25544&FORMAT=TLE`.
  Удачный ответ записывается в `data/cache/<ключ>` вместе с временем получения.
- Что работает без сети. При отказе источника берётся `data/cache/`, при его
  отсутствии — снимок репозитория `data/spaceweather/` (`goes_protons_3day.json`
  от 17.09.2026, `iss.tle` с эпохой 17.09.2026). Снимка Kp в репозитории нет:
  без сети и без кеша Kp получает статус «данных нет», и это показывается,
  а не подменяется нулём. Исторические режимы читают только локальный архив
  `data/archive_2024/` (DONKI). Расчёт орбиты и поля сети не требует:
  `skyfield` использует встроенную шкалу времени, `ppigrf` несёт коэффициенты
  IGRF в пакете, ось диполя берётся из `data/spaceweather/igrf14coeffs.txt`.
- Обновление данных: ответы источников кешируются Streamlit на 5 минут,
  чтобы движение ползунков не порождало запросы; кнопка «Обновить данные
  сейчас» в боковой панели сбрасывает этот кеш. Автоматического периодического
  обновления в текущей версии нет; давность данных показывается всегда.
- Тесты: `python -m pytest` запускает `tests/` (`pyproject.toml`,
  `testpaths`); сети не требуют.

## 3. Что делает сервис

Один экран сверху вниз: запрос → траектория → картина по времени → сравнение
окон → рекомендация → предупреждения по семи пунктам → нормы (контекст) →
данные и выгрузка.

Три результата (CONTRACT, раздел 0):

1. Картина факторов по времени вдоль траектории: модуль поля |B| по IGRF на
   всей траектории (период поиска плюс длительность, шаг 1 мин), порог
   аномалии, закрашенные пролёты аномалии, окна-кандидаты, линия горизонта
   24 ч, отметки последнего наблюдения GOES (с уровнем шкалы S) и Kp.
2. Сравнение окон одинаковой длительности: таблица по каждому механизму
   отдельно — значение каждой величины с единицей, покрытие данными и
   условия проверки по окну.
3. Рекомендация либо явный отказ с правилом. Пять исходов
   (`vkd/types.py`, `Recommendation`): `preferred` — ПРЕДПОЧТИТЕЛЬНО,
   `equivalent` — РАВНОЗНАЧНЫ, `insufficient` — ОСНОВАНИЙ НЕДОСТАТОЧНО
   (названо, чего не хватает), `all_need_check` — ВСЕ ОКНА ТРЕБУЮТ ПРОВЕРКИ,
   `trade_off` — КОМПРОМИСС. Рядом всегда печатается охват: что учтено и что
   не учтено.

Три режима (боковая панель, «Режим»):

- «Текущая обстановка» — начало периода поиска равно текущему времени UTC,
  живые источники с кешем.
- «Исторический разбор» — дата в пределах 1 мая — 30 июня 2024 и час начала;
  весь архив без отсечки.
- «Прогноз из прошлого» — та же дата, отсечка публикации равна началу
  периода; используются только записи с известным временем публикации не
  позже отсечки (раздел 5, «Отсечка»).

Запрос: длительность ВКД 60–480 мин (шаг 30), период поиска начала
0–1440 мин (шаг 60), два или три окна со сдвигом начала внутри периода.
Все времена UTC.

Два уровня интерфейса (переключатель «Уровень интерфейса»):

- «Оперативный» — вердикт сверху, картина по времени, таблица сравнения,
  не более трёх условий и трёх основных величин, кнопки выгрузки.
- «Профессиональный» — всё, включая пороги и настройки, происхождение каждой
  величины, сырые записи под каждой карточкой, панель норм, таблицу
  источников со статусами, основание допуска равнозначности.

«Что если» — стресс-сценарий (`vkd/windows/scenario.py`): задержка начала
работ 0–180 мин (сдвиг окон при прежней длительности — изменение плана),
моделируемое протонное событие с началом через заданное число минут и
уровнем 10/100/1000/10000 pfu, скачок Kp. Синтетические входы помечены
`is_simulated`, метка распространяется на весь результат и выгрузку;
у них нет времени публикации, поэтому в строгий режим они не проходят.

Устойчивость (`vkd/windows/sensitivity.py`): оценка пересчитывается на сетке
порога аномалии (порог − 2000, порог, порог + 2000 нТл) и канала захваченных
протонов (12,5 / 30 / 50 МэВ). Разброс минут в аномалии у лучшего окна по оси
порога становится допуском равнозначности (не меньше 1 мин); если
предпочтительное окно меняется на сетке, сервис печатает «ВЫБОР МЕНЯЕТСЯ
на сетке».

Надёжность: отключение источников GOES и Kp флажками в боковой панели
(отключённый источник отдаёт кеш с пометкой давности либо «данных нет»);
статусы каждого источника — «получено живьём», «из кеша, давность N мин»,
«снимок репозитория», «отказ источника, кеша нет — данных нет»; ход длительных
шагов показан индикаторами (источники, траектория, сетка устойчивости).
Отсутствие данных выражается `None` и статусом покрытия, никогда нулём.

## 4. Два механизма и охват

Обязательный охват — дословно `CONTRACT.md`, раздел 2:

| линия | статус | что даёт |
|---|---|---|
| космическая погода на траектории | **обязательна** | наблюдение GOES и Kp; внешние прогнозы NOAA и DONKI; наш расчёт условий вдоль траектории |
| статистический поток MMOD | **обязательна** | ожидаемое число попаданий по одной обоснованной модели |
| сближения SOCRATES | **отдельная линия, не обязательна** | внешний прогноз сближений станции; её отсутствие не блокирует рекомендацию, а входит в заявление об охвате |

Буря, протонное событие и радионарушение — разные явления, не складывать.
Три времени каждого сообщения ведутся раздельно: событие, срок действия,
публикация.

Что реализовано в коде на текущий момент:

- Механизм 1 «космическая погода на траектории» (`mechanism_id =
  spaceweather`, обязательный): минуты в аномалии, флюенс захваченных
  протонов по прил. А ОСТ 134-1044-2007, поток протонов GOES ≥10 МэВ,
  условия проверки по GOES, Kp и событиям DONKI.
- Механизм 2 «статистика метеороидов» (`mechanism_id = mmod_stat`,
  обязательный): величина «ожидаемое число попаданий, пластина 1 м²»
  объявлена, правило подписано «ECSS-E-ST-10-04C, Grün — спецификация A5
  ожидается». Линия подключается по спецификации ECSS/Grün (площадка А);
  сейчас интерфейс передаёт `mmod_hits = None`, покрытие линии `none`,
  пометка «линия не подключена: расчёт невозможен». Поскольку линия
  обязательна, правило п. 1 даёт исход «оснований недостаточно» с названной
  причиной — во всех режимах, пока линия не подключена.
- Линия 3 «сближения SOCRATES» (`mechanism_id = conjunctions`,
  необязательная): тип `Conjunction` и подсчёт записей с TCA в окне
  реализованы; интерфейс передаёт пустой список, в охвате печатается
  «сближения SOCRATES — нет данных».

Заключение всегда относится к объявленному охвату: под вердиктом печатается
«Охват: учтено — …; не учтено — …».

## 5. Методы кратко

Траектория (`experiments/stub_orbit.py`, временно вместо `vkd/orbit`).
TLE CelesTrak GP, NORAD 25544 → SGP4 через `skyfield.EarthSatellite`;
подспутниковая точка `wgs84.geographic_position_of` (в метаданных система
`TEME→WGS84`). Шаг 1 мин, число точек = период поиска + длительность,
до 1440 + 480 = 1920 мин, то есть до 32 ч (CONTRACT, раздел 0 и 12
«Горизонт»). Показываются источник, эпоха элементов и давность в часах.
В исторических режимах траектория строится по текущему TLE и помечена
`is_reconstruction = true` (постановка, «Исторический режим»: реконструкция
отдельно от проверяемого прогноза).

Поле и магнитные координаты. |B| в каждой точке — IGRF через `ppigrf`
(файл по умолчанию `IGRF14.shc`; в метаданных `field_model = IGRF-14
(ppigrf)`), дата вычисления — начало траектории. Параметр L — дипольное
приближение: ось диполя из g_10, g_11, h_11 файла
`data/spaceweather/igrf14coeffs.txt` на эпоху 2025.0, L = r / cos²λ_m,
B_0 = B_eq / L³. Пометка: каждая точка несёт `mag_method = dipole`,
`mag_status = approximation`; в карточке величины печатается «дипольная L —
исследовательское приближение». Отношение B/B_0 не ограничивается снизу
единицей: значения меньше 1 (несовместимость диполя и IGRF) помечаются
статусом `inconsistent_BB0` (CONTRACT, правило 1: никаких молчаливых
клампов). Вертикальная жёсткость обрезания в текущей версии не считается
(`cutoff_GV = None`); таблица Ж.1 ОСТ извлечена в `data/ost1044_cutoff/`,
но сервисом не используется.

Аномалия по порогу |B|. Точка в аномалии, если `B_nT` ниже порога
(по умолчанию 24 000 нТл, настройка 18 000–30 000). «Минут в аномалии» —
число таких точек в окне при шаге 1 мин. Порог входит в анализ устойчивости.

Поток захваченных протонов (`vkd/assess/trapped.py`). Таблица А.2.1
прил. А ОСТ 134-1044-2007 (протоны, минимум солнечной активности;
`data/ost1044_belts/A_2_1.csv`, извлечена из текста стандарта и сверена
построчно). По L — линейная интерполяция между соседними табличными
оболочками, вне сетки L = 1,14…9,0 — статус «нет модели» (`no_model_L`),
не ноль. По B/B_0 — линейная интерполяция внутри оболочки; выше
максимального табличного B/B_0 — физический ноль со статусом
`beyond_mirror`. По энергии — интегрирование по степенному закону между
узлами (log-log; точно для спектров a·E^b) от E_min до последнего узла
300 МэВ; хвост выше 300 МэВ отбрасывается, и это объявляется в правиле
величины. Флюенс за окно = сумма интегральных потоков по точкам × 60 с.
Канал E_min: 30 МэВ по умолчанию, варианты 12,5 и 50 (узлы таблицы).
Единица величины в интерфейсе — «част./(см²·ср)».

Условия по шкалам NOAA — политика прототипа (`vkd/windows/compare.py`,
`Thresholds`). GOES ≥10 МэВ ≥ 1000 pfu (S3 и выше) — приоритетное
предупреждение: окно требует срочной проверки специалистом. 10–1000 pfu
(S1–S2) — предупреждение о протонном событии, окно исключается из
автоматического выбора. Kp ≥ 7 (G3) — триггер дополнительной проверки.
Событие DONKI или моделируемое событие, чей интервал действия (или
физический интервал) пересекает окно, — условие проверки; если конец
события неизвестен, для пересечения принимаются сутки от начала. Из индексов
NOAA не следует ни прерывание, ни продолжение ВКД; исключение помеченных
окон — консервативная политика прототипа, не норма (CONTRACT, раздел 4,
п. 2). Уровень S для отметки на графике — по порогам NOAA 10/100/1000/
10 000/100 000 pfu (`app/norms.py`).

GOES как наблюдение. Берётся последнее значение канала ≥10 МэВ; если оно
старше настройки свежести (60 мин по умолчанию), покрытие механизма
становится частичным, и рекомендации нет. Поток GOES — индикатор события на
геостационарной орбите, не поток у станции.

Правило рекомендации (`recommend`, по CONTRACT, раздел 4):

1. Охват: у обязательной линии покрытие не полное → `insufficient`, названо,
   чего не хватает.
2. Условия: окна с условиями проверки исключаются из автоматического выбора;
   ни одного без условий → `all_need_check`; одно → оно предпочтительно.
3. Сравнение по механизму 1: минуты в аномалии, затем флюенс; результат
   печатается как «HH:MMZ: N мин в аномалии против M».
4. Сведение: окно предпочтительно, если лучше по механизму 1 и другие линии
   не противоречат.
5. Допуск равнозначности: разница минут в аномалии меньше допуска →
   `equivalent`; допуск — разброс на сетке устойчивости.

Отсечка по времени публикации (`vkd/assess/cutoff.py`; CONTRACT, раздел 10
и R4). В режиме «Прогноз из прошлого» каждая использованная запись
проверяется отдельно: время публикации неизвестно → исключена как
непригодная для строгого воспроизведения; опубликована после отсечки →
исключена; наблюдение с моментом позже отсечки внутри записи, опубликованной
раньше (вложенные `allKpIndex`), → исключено; своевременный внешний прогноз
на будущее — разрешён (R6). Список исключённых записей с причинами попадает
в снимок расчёта (`history.excluded_by_cutoff` в JSON-выгрузке).
Датированные выпуски для строгого режима — уведомления DONKI
`sentNotifications` с `messageIssueTime`; карточки SEP — с `submissionTime`
и `versionId`.

## 6. Обоснование порогов

По CONTRACT 4.2 и `docs/KRITERII_PLAN.md` 7.1. Все пороги — поля
`Thresholds` в `vkd/windows/compare.py`; в профессиональном уровне порог
аномалии, канал и свежесть GOES задаются в боковой панели.

| порог | значение | источник | чем является |
|---|---|---|---|
| предупреждение по GOES ≥10 МэВ (`goes_p10_warning_pfu`) | 10 pfu, S1 | NOAA SWPC, Space Weather Scales | граница шкалы — норма NOAA; исключение окна из автовыбора — политика прототипа |
| приоритетное предупреждение (`goes_p10_priority_pfu`) | 1000 pfu, S3 | NOAA SWPC, Space Weather Scales (S3: избегать радиационной опасности при ВКД) | граница шкалы — норма NOAA; «срочная проверка специалистом» — политика прототипа, не команда |
| триггер проверки по Kp (`kp_check`) | Kp ≥ 7, G3 | NOAA SWPC, шкала G | выбор команды, политика прототипа |
| сближение с TCA в окне | наличие записи, без порога промаха | CelesTrak SOCRATES (линия не подключена) | ручная оценка; порог промаха как вероятность попадания не вводится |
| порог аномалии (`saa_B_threshold_nT`) | 24 000 нТл, настройка 18 000–30 000 | инженерная оценка для высоты ~420 км | настройка прототипа, проверяется на сетке ±2000 нТл |
| канал захваченных протонов (`e_min_MeV`) | 30 МэВ; варианты 12,5 и 50 | узлы таблицы А.2.1 ОСТ 134-1044-2007 | настройка, варьируется в устойчивости |
| свежесть GOES для будущих участков (`goes_max_age_min`) | 60 мин, настройка 10–360 | инженерная настройка | политика прототипа: старше — покрытие частичное |
| допуск равнозначности (`equiv_tol_min`) | разброс минут в аномалии на сетке порога, не меньше 1 мин | CONTRACT 4.5 | наш расчёт из чувствительности; 5 мин по умолчанию в `Thresholds` перекрывается в приложении |
| конец события неизвестен | принимаются сутки от начала | `compare.py`, `assess_window` | допущение прототипа |

Нормы в панели «Нормы» — справочный контекст, не пороги и не вердикт по

## 8. Формат выгрузки

Блок «Данные и выгрузка», две кнопки. Экран и обе выгрузки строятся из
одного словаря-снимка, собранного один раз за расчёт (CONTRACT, правило 10).

JSON (`vkd_risk_<время>.json`) — полный снимок: версия алгоритма, время
расчёта, режим, уровень, запрос, метаданные траектории, окна с механизмами
и величинами, рекомендация, карточки, источники со статусами, объявленный и
недостающий охват, `policy_note`, признак и параметры сценария, история
(поставщик, исключённые отсечкой записи, использованные события),
устойчивость (сетка, разброс, предпочтительное окно в каждой точке сетки).

ZIP (`vkd_risk_<время>.zip`, `app/export.py`):

| файл | содержимое |
|---|---|
| `report.md` | читаемый отчёт: режим, версия алгоритма, отсечка, запрос, траектория, окна с величинами и условиями, рекомендация, допуск, охват, «Чего не заявляем» |
| `request.json` | `t0_utc`, `duration_min`, `search_min`, начала окон, пороги `Thresholds`, отключённые источники, `cutoff_utc`, `T_months` |
| `trajectory_meta.json` | источник, метод `sgp4`, система координат, эпоха, период покрытия, признак реконструкции, модель поля, модуль орбиты |
| `factors.json` | по каждому окну — механизмы, покрытие, условия, величины с единицей, происхождением, наличием воздействия, покрытием, ссылками на записи, правилом и ограничениями |
| `recommendation.json` | вердикт, правило, причины, чего не хватает, предпочтительное окно, сравнение по механизмам, основание допуска |
| `cards.json` | карточки предупреждений по семи пунктам |
| `sources.json` | статус каждого источника: живой ответ или кеш, время получения, момент данных, давность, эпоха TLE |
| `manifest.json` | версия алгоритма, время расчёта, отсечка, `source_versions` (те же статусы источников), список идентификаторов сырых записей, пороги |
| `raw/<record_id>.json` | сырые записи: последняя запись GOES, запись Kp, использованные уведомления и карточки DONKI, текст TLE с эпохой и статусом получения (в именах файлов `/`, `#`, `:` заменены) |

Как восстановить расчёт из архива. Функции импорта архива в сервисе нет;
восстановление ручное: взять код версии из `manifest.json`
(`algorithm_version`), выставить в боковой панели режим, дату и час (или
`t0_utc`), длительность, период поиска, сдвиги окон, пороги, отключённые
источники и `T_months` из `request.json`; в истории отсечка равна началу
периода. Значения источников, которые вошли в расчёт, лежат в `raw/`
(последние записи GOES и Kp, события DONKI, TLE): при совпадении сырых
записей значения в `factors.json` воспроизводятся тем же кодом. Для точного
повтора траектории три строки TLE из поля `text` файла `raw/iss.tle.json`
нужно положить в `data/cache/iss.tle` и запускать сервис без сети: живой
ответ имеет приоритет над кешем, кеш — над снимком `data/spaceweather/`.

## 11. Чего не заявляем

Дословно `CONTRACT.md`, раздел 9:

- допустимость реального выхода;
- вероятность разгерметизации и вероятность попадания в космонавта;
- дозу человека как обязательный результат;
- поток GOES как поток у станции без обрезания и без предположения о спектре;
- что учтены все внешние угрозы;
- что собственный расчёт предсказывает развитие протонного события: он
  предсказывает пересечение пространственной модели.

## 12. Ограничения текущей версии

- Временные заглушки. `app/main.py` импортирует `vkd.history`, `vkd.orbit`,
  `vkd.sources` и при `ImportError` берёт `experiments/stub_history.py`,
  `experiments/stub_orbit.py`, `experiments/stub_sources.py`. Сейчас пакеты
  области А пусты, поэтому работают заглушки; их имена печатаются в таблице
  источников и в `trajectory_meta.orbit_module`.
- Линия метеороидов не подключена: `mmod_hits = None`, покрытие обязательной
  линии `none`, поэтому вердикт во всех режимах — «оснований недостаточно»
  с названной причиной `mmod_stat: покрытие none`. Сравнение по механизму 1,
  условия, карточки и устойчивость при этом считаются и показываются.
  Исход `trade_off` (компромисс) определён в типах, но правило его не
  порождает, пока сравнивается один механизм.
- Архива GOES за 2024 год в репозитории нет: в исторических режимах поток
  GOES отсутствует, покрытие механизма 1 — `none`. Архивы NOAA NCEI
  (`3day_forecast`, `daypre`, GOES) и OEM NASA из CONTRACT, раздел 10, не
  подключены. Kp в истории берётся из карточек DONKI `allKpIndex`; у них нет
  собственного времени публикации, поэтому в «Прогнозе из прошлого» они
  исключаются и условие по Kp там не возникает.
- Реконструкция орбиты в истории: траектория за 2024 год строится по текущему
  TLE и помечена реконструкцией; исторические элементы не используются.
  Поле во всех режимах — IGRF-14, тогда как CONTRACT R5 требует IGRF-13 для
  строгой линии 2024. Жёсткость обрезания не считается; «минут доступности
  частиц канала» (CONTRACT, раздел 3) не выдаётся.
- Дипольная L — исследовательское приближение, помечено в каждой точке;
  используется только таблица минимума солнечной активности; поле
  вычисляется на дату начала траектории.
- Список записей, исключённых отсечкой, попадает в JSON-выгрузку, но не в
  ZIP; `manifest.json` не содержит SHA коммита — только `algorithm_version`.
- Автоматического периодического обновления и валидации запроса сверх границ
  ползунков нет. Карточки условий классифицируются по слову «критическое» в
  тексте причины, тогда как правило пишет «приоритетное», поэтому все условия
  сейчас показываются как ограничивающие; тексты карточек условий в
  `vkd/explain/cards.py` содержат формулировки об отмене окна и о
  прерывании либо непрерывании идущей ВКД, отменённые
  `docs/KRITERII_PLAN.md` 7.1, — расхождение зафиксировано, не исправлено.
- Единица флюенса в интерфейсе — «част./(см²·ср)», тогда как CONTRACT R3
  описывает поток прил. А как всенаправленный, част./(см²·с·МэВ), а флюенс —
  част./см²; в подписи правила величины стоит «трапеции по энергии», тогда как
  код интегрирует по степенному закону.
- Папки `examples/` с сохранёнными расчётами в репозитории пока нет;
  примеры собираются кнопками выгрузки из раздела 8.
- Линия метеороидов подключается по спецификации ECSS-E-ST-10-04C (Grün,
  случайно ориентированная пластина 1 м²): природные метеороиды на опорную
  пластину; непроверенные сезонные потоки и техногенный мусор — вне полного
  охвата (CONTRACT R7).
