# ВКД-Риск

Документ сдачи для жюри. КосмоХакатон 2026, кейс «Прогнозирование внешних
рисков и планирование ВКД на МКС», 18–20 сентября 2026.
Веб-сервис на Python (Streamlit). Языковые модели в расчёте не применяются:
данные не текстовые.

Версия алгоритма в интерфейсе и выгрузке: `0.4.1-i1` (`app/compute.py`,
`ALGO_VERSION`); версия схемы снимка `2.1`. Договор команды — `CONTRACT.md`
v3.1 с предложениями v3.2 в разделе 12 (R9–R11, Р-О1, Р-О2 — действуют как
политика прототипа до подтверждения А); типы стыка — `vkd/types.py` версии
2.1. Описание соответствует коммиту `3055dff` (ветка `codex/a1-sources`
слита: орбита A3 и архив A1/A2 подключены).

## 1. Что это и для кого

Сервис для аналитика ГОГУ (главной оперативной группы управления) при
подготовке выхода в открытый космос. Аналитик задаёт начало и длительность
ВКД и период поиска начала, а сервис получает орбиту МКС и открытые данные
о космической погоде, считает условия вдоль траектории по каждому механизму
воздействия отдельно (космическая погода на траектории и статистика природных
метеороидов), сравнивает два-три окна одинаковой длительности и выдаёт
рекомендацию либо явный отказ с видимым правилом, охватом и списком
недостающих данных. Это исследовательский прототип поддержки решений: допуск
к реальной ВКД остаётся за уполномоченными специалистами, и сервис его не
выдаёт.

Развёрнутое решение: `<ссылка появится после развёртывания>`.

## 2. Запуск за три команды

```
python -m pip install -r requirements.txt
python -m streamlit run app/main.py
python -m pytest
```

- Python 3.12–3.14. Проверено на 3.14.6 (Windows): 97 проверок и 559
  подпроверок проходят. `pyproject.toml` допускает `>=3.11` (`tomllib` для
  файла настроек). Версии зависимостей закреплены точно
  в `requirements.txt` (numpy 2.5.1, pandas 2.3.3, scipy 1.18.0, sgp4 2.27,
  skyfield 1.55, ppigrf 2.1.0, requests 2.34.2, plotly 5.24.1,
  streamlit 1.64.0, python-dotenv 1.2.3, pytest 9.1.1).
- Ключи API не нужны. Единственная переменная окружения — `VKD_SETTINGS`
  (путь к файлу настроек вместо `config/settings.toml`, раздел 14); `.env` и
  `st.secrets` не читаются; `.gitignore` исключает `.env`,
  `.streamlit/secrets.toml` и `data/cache/`.
- Адрес сервиса печатает Streamlit в терминале (по умолчанию
  `http://localhost:8501`); `.streamlit/config.toml` задаёт `headless = true`,
  браузер сам не открывается.
- Что требует сети. В любом режиме при загрузке страницы сервис пробует
  живые запросы (тайм-аут `[sources].timeout_s` = 6 с на адрес,
  `experiments/stub_sources.py`, адреса — `config/settings.toml`):
  GOES `services.swpc.noaa.gov/json/goes/primary/integral-protons-3-day.json`,
  Kp `kp.gfz.de/app/json/` за последние двое суток, TLE — цепочка из трёх
  адресов по порядку (`celestrak.org/NORAD/elements/gp.php?CATNR=25544`,
  `api.wheretheiss.at/v1/satellites/25544/tles`,
  `tle.ivanstanojevic.me/api/tle/25544`): первый разобранный ответ идёт в
  расчёт, адрес — в манифест орбиты, отказавшие перечисляются в статусе.
  Удачный ответ записывается в `data/cache/<ключ>` вместе с временем получения.
- Что работает без сети. При отказе источника берётся `data/cache/`, при его
  отсутствии — снимок репозитория `data/spaceweather/` (`goes_protons_3day.json`
  от 17.09.2026, `iss.tle` с эпохой 17.09.2026); статус источника при этом
  «отказ источника: кеш» или «снимок репозитория» с давностью. Снимка Kp в
  репозитории нет: без сети и без кеша Kp получает статус «данных нет», и это
  показывается, а не подменяется нулём. Орбита текущего режима требует TLE
  не старше `tle_max_age_days` (3 сут) относительно обеих границ горизонта:
  устаревший снимок даёт «орбита недоступна», покрытие обязательной линии
  отсутствует, вердикт `insufficient`, заглушка не подставляется (Р-О2), —
  текущий режим без сети живёт только на свежем кеше. Исторические режимы
  сети не требуют: архив DONKI `data/archive_2024/` и реестр A1
  `data/source_registry_2024/` (выпуски NOAA, OEM NASA/JSC, тела сообщений
  DONKI). Расчёт поля и метеороидов сети не требует: `skyfield` использует
  встроенную шкалу времени, коэффициенты IGRF-13/14 лежат в
  `data/orbit/*.shc` и проверяются по хешам `data/orbit/manifest.json`,
  карта аномалии берёт встроенные коэффициенты `ppigrf`, множители ECSS
  зашиты в `vkd/assess/meteoroids.py`.
- Обновление данных. В текущем режиме — автообновление по таймеру
  (боковая панель, «Автообновление в текущем режиме, мин»: 0 / 5 / 10 / 15,
  по умолчанию 5; фрагмент Streamlit очищает кеш и перезапускает расчёт,
  печатает время последнего обновления) и кнопка «Обновить данные сейчас»
  для принудительного обновления. Ответы источников кешируются Streamlit на
  5 минут, чтобы движение ползунков не порождало запросы. Давность данных
  показывается всегда.
- Тесты: `python -m pytest -q` запускает `tests/` (`pyproject.toml`,
  `testpaths`): 97 проверок и 559 подпроверок, около 40 с, сети не требуют.
  `tests/orbit`, `tests/history`, `tests/sources` написаны на `unittest`
  (область А), pytest собирает их вместе с остальными.
- Сохранённые примеры: `examples/` (9 расчётов, JSON и ZIP, индекс в
  `examples/INDEX.md`; `examples/experiments/forecast_lines.json` — окна
  эксперимента раздела 10); пересоздать — `python scripts/make_examples.py`;
  воспроизвести любой — `python scripts/replay_example.py examples/<имя>.zip`
  (раздел 8).

## 3. Что делает сервис

Один экран сверху вниз: запрос → траектория (источник, эпоха элементов или
дата создания OEM, давность, метод, статус строгости) → баннеры режима и
сценария → наблюдения за последние дни (текущий режим) или прогноз NOAA,
выпущенный до отсечки (исторические режимы) → картина по времени → карта
трассы → сравнение окон → рекомендация → предупреждения по семи пунктам →
нормы (контекст) → данные и выгрузка. Интерфейс (`app/main.py`) только
рендерит снимок, который собирает конвейер `app/compute.py` (`run()`); тот же
конвейер строит выгрузку, примеры и повторы.

Три результата (CONTRACT, раздел 0):

1. Картина факторов по времени вдоль траектории: модуль поля |B| по IGRF на
   всей траектории (период поиска плюс длительность, шаг 1 мин), порог
   аномалии, закрашенные пролёты аномалии, окна-кандидаты, линия конца
   периода начала (24 ч), отметки последнего наблюдения GOES (с уровнем
   шкалы S) и Kp, линии событий с временем публикации (фиолетовые) и
   моделируемых событий сценария. Дополнительно — карта трассы
   (`app/viz.py`): область аномалии как точки сетки 4°, где |B| по IGRF на
   средней высоте трассы ниже порога, трасса за весь горизонт, окна цветом,
   точки трассы в аномалии; в текущем режиме — панель наблюдений
   (`app/obs.py`, `observations_panel`): ряды GOES ≥10 МэВ и Kp из кеша
   источников с линиями порогов S1/S2/S3 и G1/G3/G5 и отметкой момента
   запроса; в исторических режимах — панель прогноза NOAA
   (`forecast_panel`): прогноз Kp по 3-часовым интервалам и суточные
   вероятности S1+ и протонного события из выпусков до отсечки, с отметкой
   отсечки и горизонта.
2. Сравнение окон одинаковой длительности: график (минуты в аномалии
   столбцами, флюенс точками на логарифмической оси, ожидаемое число
   попаданий метеороидов подписью; окна под условием выделены красным) и
   таблица по каждому механизму отдельно — значение каждой величины с
   единицей, покрытие данными и условия проверки по окну.
3. Рекомендация либо явный отказ с правилом. Пять исходов
   (`vkd/types.py`, `Recommendation`): `preferred` — ПРЕДПОЧТИТЕЛЬНО,
   `equivalent` — РАВНОЗНАЧНЫ, `trade_off` — КОМПРОМИСС (механизмы указывают
   на разные окна), `insufficient` — ОСНОВАНИЙ НЕДОСТАТОЧНО (названо, чего не
   хватает), `all_need_check` — ВСЕ ОКНА ТРЕБУЮТ ПРОВЕРКИ. Под вердиктом
   печатаются «что повлияло», «чего не хватает» и охват.

Три режима (боковая панель, «Режим»):

- «Текущая обстановка» — начало периода поиска равно текущему времени UTC,
  живые источники с кешем, автообновление.
- «Исторический разбор» — дата в пределах 1 мая — 30 июня 2024 и час начала;
  весь архив без отсечки; орбита — OEM NASA/JSC как реконструкция; баннер
  «не является проверяемым прогнозом».
- «Прогноз из прошлого» — та же дата, отсечка публикации равна началу
  периода; используются только записи с известным временем публикации не
  позже отсечки, прогнозы NOAA — из выпусков до отсечки; баннер с числом
  исключённых записей (раздел 5, «Отсечка»).

Запрос: длительность ВКД 60–480 мин (шаг 30), период поиска начала
0–1440 мин (шаг 60), два или три окна со сдвигом начала внутри периода.
Все времена UTC.

Два уровня интерфейса (переключатель «Уровень интерфейса»):

- «Оперативный» — вердикт сверху, наблюдения, картина по времени, карта
  свёрнута, график и таблица сравнения, не более трёх условий и трёх
  основных величин, кнопки выгрузки.
- «Профессиональный» — всё, включая пороги и настройки (порог аномалии,
  канал, свежесть GOES, триггер Kp, допустимый возраст TLE — поверх
  `config/settings.toml`), ограничения орбитального модуля, происхождение
  каждой величины, ссылки на первоисточник и сырые записи под каждой
  карточкой, таблицу устойчивости на сетке порогов, таблицу учтённых
  событий, панель норм, таблицу источников со статусами, поставщика истории
  и список исключённых отсечкой записей.

«Что если» — стресс-сценарий (`vkd/windows/scenario.py`): задержка начала
работ 0–180 мин (сдвиг окон при прежней длительности — изменение плана, не
улучшение условий), моделируемое протонное событие с началом через заданное
число минут и уровнем 10/100/1000/10000 pfu, скачок Kp. Синтетические
входы помечены `is_simulated`, метка распространяется на весь результат и
выгрузку (баннер «Моделируемый сценарий»); у них нет времени публикации,
поэтому в строгий режим они не проходят и в кеш не попадают. Панель
сценария доступна во всех режимах.

Устойчивость (`vkd/windows/sensitivity.py`): оценка пересчитывается на сетке
порога аномалии (порог − 2000, порог, порог + 2000 нТл) и канала захваченных
протонов (12,5 / 30 / 50 МэВ) с нулевым допуском внутри сетки. Разброс минут
в аномалии у лучшего окна по оси порога становится допуском равнозначности
(не меньше 1 мин); если предпочтительное окно меняется на сетке, сервис
печатает «ВЫБОР МЕНЯЕТСЯ на сетке» и раскрывает таблицу сетки.

Надёжность: у источников GOES и Kp три состояния в боковой панели —
«включён», «отказ: только кеш» (живого запроса нет, кеш с давностью,
покрытие частичное и объявлено) и «исключён: нет данных» (обязательная
линия без покрытия → «оснований недостаточно», экран не падает); значение
попадает в `request.disabled` снимка. Статусы каждого источника —
«получено живьём с <адрес>», «отказ источника: кеш, давность N мин»,
«снимок репозитория», «отказ всех адресов TLE (…)», «источник исключён
пользователем — данных нет». Ошибка орбитального модуля (устаревший TLE,
непокрытый OEM) — статус «орбита недоступна», не заглушка. Ход шагов
показан индикаторами (источники; траектория, поле, оценка, устойчивость;
область аномалии на карте). Отсутствие данных выражается `None` и статусом
покрытия, никогда нулём; частичное покрытие объявляется в причинах и не
блокирует рекомендацию.

## 4. Два механизма и охват

Обязательный охват — дословно `CONTRACT.md`, раздел 2:

| линия | статус | что даёт |
|---|---|---|
| космическая погода на траектории | **обязательна** | наблюдение GOES и Kp; внешние прогнозы NOAA и DONKI; наш расчёт условий вдоль траектории |
| статистический поток MMOD | **обязательна** | ожидаемое число попаданий по одной обоснованной модели |
| сближения SOCRATES | **отдельная линия, не обязательна** | внешний прогноз сближений станции; её отсутствие не блокирует рекомендацию, а входит в заявление об охвате |

Буря, протонное событие и радионарушение — разные явления, не складывать.
Три времени каждого сообщения ведутся раздельно: событие, срок действия,
публикация.

Что реализовано в коде:

- Механизм 1 «космическая погода на траектории» (`mechanism_id =
  spaceweather`, обязательный): минуты в аномалии, флюенс захваченных
  протонов по прил. А ОСТ 134-1044-2007, поток протонов GOES ≥10 МэВ; в
  исторических режимах ещё три внешних прогноза NOAA из выпусков до
  отсечки (максимум прогноза Kp в окне, суточные вероятности S1+ и
  протонного события); условия проверки по GOES, Kp, датированным
  событиям DONKI (протонные события, бури с Kp ≥ 7, прогноз прихода
  выброса WSA-ENLIL) и прогнозу Kp NOAA.
- Механизм 2 «статистика метеороидов» (`mechanism_id = mmod_stat`,
  обязательный, `vkd/assess/meteoroids.py`): ожидаемое число попаданий
  природных метеороидов массой не менее 10⁻³ г на одностороннюю случайно
  кувыркающуюся пластину 1 м² за окно по ECSS-E-ST-10-04C Rev.1 —
  поток Grün (формула 10-1) × множители Table J-6 по фактической высоте
  каждой точки трассы, интеграл по времени × площадь
  (`meteoroid_hits_track`, спецификация А `docs/methods/METEOROIDS_GRUN_SPEC.md`).
  Трасса покрывает меньше 95 % окна → покрытие частичное. Метеорные потоки
  конкретной даты и техногенный мусор не включены, и это объявляется в
  правиле величины. Вне диапазонов Table J-5 (масса) и Table J-6 (высота
  100…100 000 км) — отказ «вне области применимости ECSS», не кламп.
- Линия 3 «сближения SOCRATES» (`mechanism_id = conjunctions`,
  необязательная): тип `Conjunction` и подсчёт записей с TCA в окне
  реализованы; конвейер передаёт пустой список, в охвате печатается
  «сближения SOCRATES — нет данных».

Заключение всегда относится к объявленному охвату: под вердиктом и в
`report.md` печатается «Охват: учтено — космическая погода на траектории,
природные метеороиды ECSS/Grün; не учтено — сближения SOCRATES — нет
данных, метеорные потоки конкретной даты — не включены, техногенный мусор
статистически — не включён» (`vkd/windows/compare.py`, `coverage_declared`,
`coverage_missing`).

## 5. Методы кратко

Траектория (`vkd/orbit`, область А, A3; подключена мостом
`vkd/integration/orbit_bridge.py`, заглушки орбиты нет). Текущий режим:
TLE NORAD 25544 от слоя источников кладётся в
`data/cache/orbit_root/<sha12>/` с манифестом (SHA-256, время получения,
адрес) и копиями коэффициентов IGRF, модуль А проверяет байты снимка по
хешам; SGP4/WGS72 (`sgp4`, `skyfield`), геодезические координаты WGS84
(в метаданных `method = sgp4`, `frame = TEME -> ITRS / WGS84`,
`source_id = celestrak_gp`). Обе границы горизонта не дальше
`tle_max_age_days` (3 сут) от эпохи TLE — инженерный предел, не оценка
ошибки; иначе «орбита недоступна» (Р-О2). Исторические режимы: NASA/JSC
OEM из реестра A1 (26 файлов, покрытие 29 апреля — 13 июля 2024),
кусочная кубическая интерполяция Эрмита, EME2000 → ITRS/WGS84
(`method = oem_interp`, `source_id = nasa_jsc_oem`). Строгий отбор OEM по
доказанной публикации до отсечки не проходит (публичная доступность
версии в 2024 году не доказана), поэтому берётся OEM, созданный и
изменённый в S3 не позднее отсечки, как ОБЪЯВЛЕННАЯ реконструкция
(`strictness = declared_reconstruction`, `is_reconstruction = true`,
ограничение в происхождении и на экране; Р-О1 — решение Б, ждёт
подтверждения А). Шаг 1 мин, начало и конец включены: число точек =
период поиска + длительность + 1, до 1921 (32 ч; CONTRACT, раздел 0 и 12
«Горизонт»). Показываются источник, эпоха элементов (в истории — дата
создания OEM), давность в часах, метод и статус. Отчёт происхождения А
(`trajectory_with_provenance`: записи с SHA-256, сегменты, ограничения)
входит в снимок (`trajectory_meta.provenance`) и в выгрузку
(`raw/orbit_provenance.json`). В текущем режиме текст TLE сохраняется в
снимке для повтора; в истории повтор от TLE не зависит.

Поле и магнитные координаты. |B| в каждой точке — полная модель IGRF до
степени 13 на момент точки (A3, `ppigrf` с коэффициентами
`data/orbit/IGRF13.shc` для 2024 года и `IGRF14.shc` для текущих дат,
хеши в `data/orbit/manifest.json`; в метаданных `field_model = IGRF-13`
или `IGRF-14`; вне таблицы коэффициентов — отказ без экстраполяции). A3
отдаёт также L, B/B_0 и вертикальную жёсткость обрезания Стёрмера
центрального наклонённого диполя (статус `approximation`), но для входа в
таблицы ОСТ конвейер их не использует: центральный диполь в ядре аномалии
даёт L ≈ 1,07 — ниже первой оболочки таблицы (1,14), а вне ядра B/B_0
уходит за точку отражения, и флюенс на всей трассе получался тождественно
нулевым. Вместо этого `vkd/assess/magcoords.py` (R11) считает L и B_0 от
центра эксцентричного диполя: ось из g_10, g_11, h_11, смещение центра по
квадрупольным членам того же IGRF (Fraser-Smith 1987) на дату средней
точки трассы — около 600 км (≈0,08 R_E) в сторону западной части Тихого
океана; L = r' / cos²λ'_m, B_0 = B_eq / L³, B — полное IGRF точки от A3.
Каждая точка несёт `mag_method = dipole`, `mag_status = approximation`; в
карточке величины печатается «дипольная L — исследовательское
приближение»; сводка (смещение, число точек, число помеченных) — в
`trajectory_meta.belt_coordinates`. В сохранённых примерах модель есть у
76–87 % точек окна, поэтому покрытие флюенса частичное и объявляется.
Отношение B/B_0 не ограничивается снизу единицей: значения меньше 1
помечаются статусом `inconsistent_BB0` (CONTRACT, правило 1: никаких
молчаливых клампов; 17–41 точка на трассу в примерах). Жёсткость
обрезания в оценке не используется (значение A3 остаётся в точке, «минут
доступности частиц канала» не выдаётся); таблица Ж.1 ОСТ извлечена в
`data/ost1044_cutoff/`, но сервисом не используется. Область аномалии на
карте (`app/viz.py`) считается отдельно на сетке 4° встроенными
коэффициентами `ppigrf`.

Аномалия по порогу |B|. Точка в аномалии, если `B_nT` ниже порога
(по умолчанию 24 000 нТл, настройка 18 000–30 000). «Минут в аномалии» —
число таких точек в окне при шаге 1 мин. Порог входит в анализ устойчивости.

Поток захваченных протонов (`vkd/assess/trapped.py`). Таблица А.2.1
прил. А ОСТ 134-1044-2007 (протоны, минимум солнечной активности;
`data/ost1044_belts/A_2_1.csv`, извлечена из текста стандарта и сверена
построчно). По L — линейная интерполяция между соседними табличными
оболочками, вне сетки L = 1,14…9,0 — статус «нет модели» (`no_model_L`),
не ноль. По B/B_0 — линейная интерполяция внутри оболочки; выше
максимального табличного B/B_0 — физический ноль со статусом
`beyond_mirror`. По энергии — интегрирование по степенному закону между
узлами (log-log; точно для спектров a·E^b; трапеции на сетке ОСТ завышали
бы интеграл спектра E⁻² более чем на 20 %) от E_min до последнего узла
300 МэВ; хвост выше 300 МэВ отбрасывается, и это объявляется в правиле
величины. Поток прил. А — всенаправленный; флюенс за окно = сумма
интегральных потоков по точкам × 60 с, единица «част./см²». Канал E_min:
30 МэВ по умолчанию, варианты 12,5 и 50 (узлы таблицы). Покрытие величины —
доля точек окна, для которых у таблицы есть модель.

Метеороиды (`vkd/assess/meteoroids.py`, реализация Б по спецификации А
`docs/methods/METEOROIDS_GRUN_SPEC.md`, версия `grun-ecss-2020-v1`). Поток
Grün на 1 а.е. F_met,0(m) = 3,15576·10⁷·(F_1 + F_2 + F_3) (формула 10-1
ECSS-E-ST-10-04C Rev.1, с. 76–77; воспроизводит Table J-5 стандарта на
30 массах 10⁻¹²…10² г с точностью 0,6 %); поправки низкой орбиты
F = F_0·G·s_f·K по Annex C, формула (C-25), множители Table J-6 линейно по
высоте (на 400 км G = 2,00, s_f = 0,63, K = 1,09). По окну
(`meteoroid_hits_track`): F по фактической высоте каждой точки трассы,
интеграл трапециями по фактическим интервалам dt, начало и конец окна
включены, N = A·∫F dt / 31 557 600 с; число точек само по себе не
добавляет минуты экспозиции. Контрольное число: 400 км, 1 м², 6 ч,
m ≥ 10⁻³ г → N = 5,609728·10⁻⁷, совпадает с контрольными данными А
(`data/meteoroids/grun_reference.json`) с относительной точностью 10⁻¹⁰.
Модель изотропна и от наклонения не зависит; неопределённость потока по
стандарту ×0,33…3 (J.2.3.2) хранится в объекте результата.

Условия — политика прототипа (`vkd/windows/compare.py`, `Thresholds`;
значения — `config/settings.toml`, раздел 14). GOES ≥10 МэВ ≥ 1000 pfu
(S3 и выше) — приоритетное предупреждение: окно требует срочной проверки
специалистом. 10–1000 pfu (S1–S2) — предупреждение о протонном событии,
окно исключается из автоматического выбора. Kp ≥ 7 (G3, `kp_check`) —
триггер дополнительной проверки; тот же порог применяется к наблюдению
Kp, уведомлению DONKI о буре, прогнозу WSA-ENLIL и прогнозу NOAA.
Датированные события (в том числе моделируемые), чей интервал действия
или физический интервал пересекает окно, дают условие только четырёх
видов (R10): протонное событие SEP — карточка или уведомление
(«приоритетное», если в записи есть слово «приоритет»); геомагнитная буря
GST — только если в теле уведомления (реестр A1) назван Kp ≥ 7, уровень
не назван → условие с пометкой (консервативно), Kp ниже порога →
информация в картине; прогноз прихода выброса к Земле (`CME_ARRIVAL`,
WSA-ENLIL из карточек CME DONKI: `estimatedShockArrivalTime`,
длительность, ожидаемый Kp по полю `[history].enlil_kp_fields` = `kp_90` —
типичная оценка, верхняя `kp_180` остаётся в тексте; публикация = время
завершения прогона) с ожидаемым Kp ≥ 7; прогноз Kp NOAA (3-day forecast
из выпуска до отсечки) с максимумом в окне ≥ 7 (R9) — помечен словом
«прогноз», карточка `external_forecast`. Вспышки и сами выбросы остаются
информацией в картине (по эксперименту на контрольной неделе «любое
событие → условие» давало 113 ложных пометок, раздел 10). Связанные записи
одного события — уведомление, карточки по приборам, несколько прогонов
модели (разрыв начал до 12 ч, для ENLIL 6 ч) — сводятся в одно условие с
перечнем идентификаторов записей (Т3); идентификаторы и ссылки на
первоисточник печатаются в карточке условия. Если конец события
неизвестен, для пересечения принимаются сутки от начала. Из индексов NOAA
не следует ни прерывание, ни продолжение ВКД; исключение помеченных окон —
консервативная политика прототипа, не норма (CONTRACT, раздел 4, п. 2).
Уровень S для отметки на графике — по порогам NOAA
10/100/1000/10 000/100 000 pfu (`app/norms.py`).

Прогнозы NOAA в исторических режимах (`vkd/integration/noaa_forecast.py`
→ `vkd/history/replay.py`, A2). Три канала из реестра A1: планетарный Kp
по 3-часовым интервалам и суточная вероятность S1+ (3-day forecast NOAA
NCEI), суточная вероятность протонного события (daypre). Берётся последний
допустимый выпуск с временем `Issued` не позже отсечки (в разборе — не
позже начала периода); ячейки сохраняют исходное разрешение — суточная
вероятность не пересчитывается в вероятность за окно, и это подписано;
покрытие окна ячейками объявляется (≥95 % полное, ≥50 % частичное);
отсутствие выпуска (разрыв каталога 3-day forecast 15.05–16.06.2024) даёт
статус «нет допустимого выпуска» и оценку не блокирует. Текст выбранного
бюллетеня попадает в сырые записи выгрузки.

GOES как наблюдение и покрытие канала. Берётся последнее значение канала
≥10 МэВ; свежее настройки (60 мин по умолчанию) — покрытие полное, старше —
частичное с пометкой «устарело для будущих участков». В исторических
режимах наблюдений GOES нет: если к отсечке есть датированные уведомления
DONKI о протонных событиях — покрытие канала частичное «канал частично
покрыт уведомлениями»; если окно целиком внутри периода каталога DONKI
(1 мая — 1 июля 2024) и уведомлений нет — покрытие частичное «протонных
событий не объявлено» (пустой каталог за покрытый период — результат, не
отсутствие данных, CONTRACT, правило 9). Поток GOES — индикатор события на
геостационарной орбите, не поток у станции.

Покрытие и правило рекомендации (`recommend`, по CONTRACT, раздел 4).
Покрытие по точкам окна: не менее 95 % — полное, не менее 50 % — частичное,
иначе отсутствует; покрытие механизма — минимум по его величинам.

1. Охват: у обязательной линии покрытие отсутствует → `insufficient`,
   названо, чего не хватает; частичное покрытие объявляется в причинах
   («покрытие частичное — объявлено») и не блокирует.
2. Условия: окна с условиями проверки исключаются из автоматического выбора;
   ни одного без условий → `all_need_check`; одно → оно предпочтительно.
3. Сравнение по каждому механизму отдельно: космопогода — минуты в аномалии,
   затем флюенс («HH:MMZ: N мин в аномалии против M»); метеороиды — число
   попаданий, окна считаются неразличимыми при относительной разнице
   меньше 5 %.
4. Сведение: механизмы указывают на разные окна и разница по космопогоде
   вне допуска → `trade_off` без победителя; иначе окно предпочтительно,
   если лучше по космопогоде и линия метеороидов не противоречит.
5. Допуск равнозначности: разница минут в аномалии меньше допуска →
   `equivalent`; допуск — разброс на сетке устойчивости.

Отсечка по времени публикации (`vkd/assess/cutoff.py`; CONTRACT, раздел 10
и R4). В режиме «Прогноз из прошлого» каждая использованная запись
проверяется отдельно: время публикации неизвестно → исключена как
непригодная для строгого воспроизведения; опубликована после отсечки →
исключена; наблюдение с моментом позже отсечки внутри записи, опубликованной
раньше (вложенные `allKpIndex`), → исключено; своевременный внешний прогноз
на будущее — разрешён (R6). Список исключённых записей с причинами
показывается в блоке «Данные» (профессиональный уровень) и сохраняется в
снимке и в `manifest.json`. Датированные выпуски для строгого режима —
уведомления DONKI `sentNotifications` с `messageIssueTime`; карточки SEP —
с `submissionTime` и `versionId`. Kp из карточек DONKI: `observedTime` —
конец трёхчасового интервала (сверено с рядом GFZ за 10.05.2024).

## 12. Чего не заявляем

Дословно `CONTRACT.md`, раздел 9:

- допустимость реального выхода;
- вероятность разгерметизации и вероятность попадания в космонавта;
- дозу человека как обязательный результат;
- поток GOES как поток у станции без обрезания и без предположения о спектре;
- что учтены все внешние угрозы;
- что собственный расчёт предсказывает развитие протонного события: он
  предсказывает пересечение пространственной модели.

`policy_note` из снимка расчёта (`app/compute.py`, `POLICY_NOTE`):
«Исключение окон с S1–S2, Kp ≥ 7 или сообщением о сближении из
автоматического выбора — консервативная политика прототипа, не
эксплуатационная норма; из индексов NOAA не следует ни прерывание, ни
продолжение ВКД.»

Дополнительно по метеороидам (CONTRACT R7): ECSS оценивает природные
метеороиды на одну опорную пластину; вероятность повреждения скафандра и
попадания в космонавта из числа попаданий не выводится; техногенный мусор и
метеорные потоки конкретной даты — вне охвата.

  `experiments/stub_sources.py`,
  `experiments/stub_history.py`. Сейчас пакеты области А пусты, поэтому
  работают заглушки; их имена печатаются в таблице источников (`_layers`)
  и в `trajectory_meta.orbit_module`.
- Архива GOES за 2024 год в репозитории нет: в исторических режимах поток
  GOES отсутствует, покрытие канала частичное — по датированным
  уведомлениям DONKI либо по факту покрытия каталога. Архивы NOAA NCEI
  (`3day_forecast`, `daypre`, GOES) и OEM NASA из CONTRACT, раздел 10, не
  подключены. Kp в истории берётся из карточек DONKI `allKpIndex`; у них нет
  собственного времени публикации, поэтому в «Прогнозе из прошлого» они
  исключаются и условие по Kp там не возникает.
- Реконструкция орбиты в истории: траектория за 2024 год строится по текущему
  TLE, помечена реконструкцией, текст TLE сохраняется в снимке для повтора;
  исторические элементы не используются. Поле во всех режимах — IGRF-14,
  тогда как CONTRACT R5 требует IGRF-13 для строгой линии 2024. Жёсткость
  обрезания не считается; «минут доступности частиц канала» (CONTRACT,
  раздел 3) не выдаётся.
- Дипольная L — исследовательское приближение (эксцентричный диполь),
  помечено в каждой точке; в ядре аномалии около 16–18 % точек трассы
  уходят ниже первой оболочки таблицы ОСТ, и покрытие флюенса из-за этого
  частичное (объявляется); используется только таблица минимума солнечной
  активности; поле вычисляется на дату начала траектории. Полностью снимает
  проблему трассировка силовой линии (`vkd/orbit`).
- Метеорные потоки конкретной даты (ECSS 10.2.2.2c) не включены — только
  спорадический фон Grün; техногенный мусор не моделируется; модель
  изотропна.
- Строки объявленного охвата в `compare.py` не обновлены после подключения
  метеороидов: под вердиктом и в `report.md` по-прежнему печатается «не
  учтено — статистика метеороидов ECSS — не подключена», хотя величина
  считается и участвует в правиле.
- В `app/main.py` панель «Что если» и панель порогов выведены внутри ветки
  текущего режима с включённым автообновлением; в исторических режимах и
  при автообновлении «0» переменные `scenario`, `th`, `T_months` не
  определяются и рендер завершается ошибкой `NameError`. Конвейер
  `app/compute.py`, примеры и повторы этим не затронуты.
- Надпись индикатора источников говорит «до 12 с», фактический таймаут 8 с;
  строка «разница < 5 %%» в сравнении по метеороидам печатается с двойным
  знаком процента.
- Линия сближений SOCRATES не подключена; автоматического перебора окон и
  валидации запроса сверх границ ползунков нет.

## Настройки вне кода

`config/settings.toml` — пороги условий, тайм-аут и адреса источников, поля Kp прогона ENLIL,
умолчания интерфейса. Путь переопределяется переменной окружения `VKD_SETTINGS`. Опечатка в ключе
порогов — ошибка при запуске, не умолчание. Всё применённое попадает в снимок и выгрузку
(`request.thresholds`, `manifest.effective_config`). Секретов в проекте нет: источники открытые.
