# Инструкция для Codex

Проект: оценка радиационного и ударного риска при выходе в открытый космос.
Второй разработчик работает с Claude Code на другой машине. Вы обмениваетесь
через этот репозиторий.

## Протокол каждой сессии

**В начале, до любой работы:**

1. `git pull`
2. Прочитать `CONTRACT.md` целиком.
3. Прочитать `journal/tim.md` — последние три записи. Особое внимание полям
   «Изменилось для товарища» и «Нужно от товарища».

## Что прочитать один раз, в первую сессию

По порядку. Дальше достаточно договора и журнала.

| файл | зачем |
|---|---|
| `CONTRACT.md` | **обязательно.** Единицы, зоны с числами, разделение областей, ABI, метод свёртки, 8 правил кода |
| `docs/ZAMYSEL.md` | **обязательно.** Тезис проекта, находки с числами, режимы, визуал, принятые поправки, порядок работ |
| `docs/STEK_VOZDEYSTVIYA_LITERATURA.md` | стек целиком, перечень воздействий с рангами, вся литература |
| `docs/zony_skafandra.md` | откуда взято каждое число поверхностной плотности |
| `docs/arhitektura_geometrii.md` | метод трассировки, материалы, перевод в Al-эквивалент |
| `docs/ARHITEKTURA.md` | базы данных, график по дням, распределение задач |

Коротко о сути: **оба главных риска сидят в одних зонах — руки, ноги,
перчатки.** По дозе рукава получают в 12 раз больше шлема, по удару там же
96 % риска (NASA, xEMU). Продукт выдаёт не число, а вердикт: когда выходить
безопаснее.

**В конце, перед завершением:**

4. Дописать запись в `journal/friend.md` по шаблону ниже. **Только в конец файла.**
5. `git add -A && git commit && git push`

## Шаблон записи журнала

```markdown
## ГГГГ-ММ-ДД ЧЧ:ММ — Codex

**Сделано:** одна-две строки, что реально работает.
**Изменилось для товарища:** что затрагивает его область, или «ничего».
**Нужно от товарища:** конкретный запрос, или «ничего».
**Заблокирован:** чем, или «нет».
```

Поле «Изменилось для товарища» — главное. Его читают в первую очередь.

## Ваша область

`src/orbit/` — TLE, распространение орбиты, трасса, магнитное поле, аномалия.
`src/impact/` — потоки частиц, попадания по зонам, карта экранирования.
`src/scene/` — трёхмерная сцена скафандра, покраска по результату.

**Файлы в `src/geometry/`, `src/radiation/`, `src/limits/`, `src/ui/`,
`include/vkd/` и `CMakeLists.txt` не редактировать.** Нужно изменение —
в журнал, в поле «Нужно от товарища», и продолжить с другой задачей.

## Файл, который правит только человек

`CONTRACT.md`. Нужно изменение — написать в журнал и остановиться на этом
пункте. Не менять самостоятельно.

## Что вы выдаёте наружу

Одна структура, определена в `CONTRACT.md` раздел 4:

```
время_utc, высота_km, широта_deg, долгота_deg, B_модуль_nT, в_аномалии_bool
```

И одно поле зоны: `area_m2`, из геометрии.

Всё остальное — внутри вашей области.

## Правила кода

Восемь правил в `CONTRACT.md`, раздел 6. Главное первое: **никаких молчаливых
клампов**. Значение вне области применимости даёт отказ с сообщением, а не
тихое приведение к границе.

Единицы входят в имя переменной: `h_km`, `lat_deg`, `B_nT`, `flux_per_cm2_s`.

## Сборка

```
scripts/setup_env.bat          настраивает MSVC, Qt, OCCT
cmake --preset mono            разработка, монолит
cmake --preset dll             показ и поставка
```

## Чего не заявлять

**Вероятность разгерметизации не считаем.** Валидированного уравнения пробоя
для многослойной ткани скафандра у нас нет. NASA потребовалось более ста
высокоскоростных выстрелов, чтобы получить его для одного пакета.

Честный результат вашей половины: **карта экранирования и ожидаемое число
попаданий частиц заданного размера по зонам.** Уравнение пробоя из ECSS
допустимо применить вторым ярусом с явной пометкой «не валидировано для ткани»
и с показом разброса.

Полный список в `CONTRACT.md` раздел 9.
