# Инструкция для Codex

Проект: оценка радиационного и ударного риска при выходе в открытый космос.
Второй разработчик работает с Claude Code на другой машине. Вы обмениваетесь
через этот репозиторий.

## Протокол каждой сессии

**В начале, до любой работы:**

1. `git status`, затем `git fetch origin`; не делать слепой pull поверх
   локальных изменений. Ветки и интеграция — `docs/TEAM_SYNC.md`.
2. Прочитать `CONTRACT.md`, открытые решения `docs/PLAN_REVIEW.md` и
   актуальное состояние `docs/PROGRESS.md`. Договор v3, типы v2 ещё не заморожены.
3. Прочитать свою задачу в `PLAN_RAZRABOTKI.md` / `docs/TEAM_SYNC.md` и
   последние три записи `journal/tim.md`, особенно изменения стыка и запросы.

## Что прочитать один раз, в первую сессию

По порядку. Дальше достаточно договора и журнала.

| файл | зачем |

история замысла и возможные дополнения, не обязательное ядро сервиса.

**В конце, перед завершением:**

4. Дописать запись в `journal/friend.md` по шаблону ниже. **Только в конец файла.**
5. Передать небольшой результат по `docs/TEAM_SYNC.md`: ID задачи, ветка/SHA,
   версия стыка, проверки и следующий шаг. Коммит/push — только в пределах
   разрешённого поручения; запрет пользователя имеет приоритет. Добавлять
   файлы адресно, не `git add -A` вслепую. Общий main интегрирует Б после проверки.
6. Во время совместной работы соединять готовые части каждые 60–90 минут
   и при передаче зависимости; после общей приёмки Б обновляет `PROGRESS.md`.

## Шаблон записи журнала

```markdown
## ГГГГ-ММ-ДД ЧЧ:ММ UTC — Codex

**Задача / версия:** ID, базовый SHA, ветка, передаваемый SHA или «локальный diff».
**Сделано:** что реально работает; исследование и планы указывать отдельно.
**Проверено:** команда, окружение, результат, путь к примеру.
**Изменилось для товарища:** что затрагивает его область, или «ничего».
**Нужно от товарища:** конкретный запрос, или «ничего».
**Заблокирован:** чем, владелец следующего действия, или «нет».
**Следующий шаг:** одна задача и точка продолжения.
```

Поле «Изменилось для товарища» — главное. Его читают в первую очередь.

## Ваша область (CONTRACT.md, раздел 5)

| пакет | что |
|---|---|
| `vkd/sources/` | обязательные текущие/архивные источники по охвату режима, реестр записей, кеш, давность и отключение |
| `vkd/orbit/` | SGP4 и исторический OEM, координаты, поле, доступные L/B/B₀/обрезание и статус метода |
| `vkd/conjunctions/` | необязательные сближения SOCRATES |
| `vkd/history/` | исторический режим: отсечка по `published_utc`, версии, replay |

Вы выдаёте типы `vkd/types.py`: `TrajectoryPoint`, `TrajectoryMeta`,
`EnvironmentSample`, `EventInterval`, `Conjunction`, а также реестр записей
и покрытие согласованного стыка. Типы пишет Claude; версия 2 пока требует
R1/R2 и фиксации семантики R8, затем явного согласования Codex.

**Не редактировать `vkd/assess/`, `vkd/windows/`, `vkd/explain/`, `vkd/suit/`,
`app/`, `experiments/`, `vkd/types.py`.** Нужно изменение — в журнал.

Архив DONKI в `data/archive_2024/` полезен для разбора. Одного
`submissionTime` карточки недостаточно для строгого прогноза: нужны
исходные датированные уведомления/версии, проверка вложенных данных.
Основной проверяемый архив NOAA и исторические OEM описаны в `docs/PLAN_REVIEW.md`.

Стык определён разделом 6 договора; схема передачи и ответственность —

## Правила кода

Правила в `CONTRACT.md`, раздел 7; обязательные проверки — раздел 8. Главное первое: **никаких молчаливых
клампов**. Значение вне области применимости даёт отказ с сообщением, а не
тихое приведение к границе.

Единицы входят в имя переменной: `h_km`, `lat_deg`, `B_nT`, `flux_per_cm2_s`.

## Запуск

Целевые команды после появления `app/main.py` и фиксации окружения:

```
python -m pip install -e ".[dev]"
streamlit run app/main.py
python -m pytest
```

На базе `efaa86d` приложения и полного набора тестов ещё нет; эти команды
не являются доказательством готовности. Точные версии/lock задаёт Б,
оба участника проверяют установку. Тесты — инварианты **и** численные проверки по независимым эталонам
(CONTRACT.md v3, раздел 7, правило 12 и раздел 8). Для SGP4 — опубликованные
тест-кейсы AIAA 2006-6753.

## Чего не заявлять

**Вероятность разгерметизации не считаем.** Валидированного уравнения пробоя
для многослойной ткани скафандра у нас нет. NASA потребовалось более ста
высокоскоростных выстрелов, чтобы получить его для одного пакета.

Результат вашей половины — проверяемые данные, траектория и история
с происхождением, единицами и ограничениями. Спецификация метеороидной
модели — ECSS/Grün; расчёт N реализует Claude в `vkd/assess/`. Это
природные метеороиды на опорную пластину, не весь MMOD и не попадания
в космонавта. Зонная геометрия/пробой остаются за пределами ядра.

Полный список в `CONTRACT.md` раздел 9.
