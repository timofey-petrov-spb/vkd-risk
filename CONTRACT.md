# CONTRACT — замороженные договорённости

Версия 2, 18.09.2026, после прочтения официальной постановки кейса.
Отменяет версию 1 (C++/Qt/DLL). Правит только человек.

Этот файл читают оба ассистента перед любой работой. Ни Claude, ни Codex
не правят его по своей инициативе: нужно изменение — в журнал, в поле
«Нужно от товарища», и остановиться.

---

## 0. Что выдаёт сервис

Не «безопасно / опасно». Допуск к реальному выходу — за уполномоченными
специалистами, это написано в постановке.

Сервис выдаёт **три вещи, всегда вместе**:

1. **Количественную картину факторов по времени** вдоль траектории станции
   на рассматриваемом интервале — по каждому механизму отдельно.
2. **Сравнение не менее двух окон одинаковой длительности**: какие факторы,
   сколько минут пересечения с неблагоприятными условиями, полнота данных.
3. **Рекомендацию либо явный отказ от рекомендации** с видимым правилом,
   которое к ней привело.

Переменная — **когда**, то есть момент начала в пределах периода поиска.
«Где» не переменная: станция там, где она есть.

## 1. Единицы

Единица входит в имя переменной. Всегда.

| величина | единица | суффикс |
|---|---|---|
| время | UTC, ISO-8601 | `_utc` |
| длительность | минуты | `_min` |
| высота | км | `_km` |
| широта, долгота | градусы | `_deg` |
| модуль поля | нТл | `_nT` |
| параметр Мак-Илвейна | безразмерный | `L` |
| отношение поля | безразмерный | `B_over_B0` |
| поток частиц | част./(см²·с·ср) | `_per_cm2_s_sr` |
| интегральный поток GOES | част./(см²·с·ср) выше порога | `_per_cm2_s_sr` |
| поверхностная плотность | г/см² | `_g_cm2` |
| площадь | м² | `_m2` |
| Kp | безразмерный, 0…9 | `kp` |

## 2. Два механизма

### Механизм 1. Космическая погода на траектории

| сигнал | наблюдение | связь с МКС | прогноз |
|---|---|---|---|
| протоны >10 МэВ | GOES, NOAA SWPC, живой | через геомагнитное обрезание по L | NOAA, DONKI (внешний) |
| Kp | GFZ, живой | граница проникновения | NOAA 3 сут (внешний) |
| структура поясов | прил. А ОСТ 1044, по L и B/B₀ | напрямую по траектории | климатология, наш расчёт |

Три времени у каждого сообщения ведутся **раздельно**: время события,
срок действия предупреждения, момент публикации.

Буря, протонное событие и радионарушение — **разные явления**. Не складывать.

### Механизм 2. Микрометеороиды и мусор

| составляющая | источник | что даёт |
|---|---|---|
| отслеживаемые объекты | CelesTrak SOCRATES | сближения со станцией и TCA |
| мелкие частицы | ГОСТ Р 25645.167-2005, ECSS 10-04C разд. 10 | статистический поток, ожидаемое число попаданий |

**Раздельно.** Сближение — предупреждение о станции, не вероятность попадания
в космонавта. Статистика — не каталог частиц.

## 3. Величины по окну

Для каждого окна-кандидата сервис считает и показывает:

| величина | единица | механизм | чьё |
|---|---|---|---|
| минут в аномалии | мин | 1 | наш расчёт |
| минут на высоких широтах (низкое обрезание) | мин | 1 | наш расчёт |
| интеграл климатического потока поясов вдоль пути | част./см² | 1 | наш расчёт |
| текущий поток протонов >10 МэВ и его тренд | част./(см²·с·ср) | 1 | наблюдение |
| уровень шкалы S и прогноз | 0…5 | 1 | внешний |
| число сближений с TCA внутри окна | шт | 2 | наблюдение SOCRATES |
| ожидаемое число попаданий на опорную площадь | шт | 2 | наш расчёт |
| полнота данных по механизму | давность, пропуски | оба | статус |

Каждая величина помечена: **наблюдение / внешний прогноз / наш расчёт**.

---

## 4. Правило рекомендации

Лексикографическое, видимое пользователю целиком.

1. Если по любому механизму **недостаточно данных** — рекомендации нет,
   названо, чего не хватает.
2. Если протонное событие идёт или спрогнозировано внутри окна — окна вне
   события предпочтительнее окон с пересечением. Если все пересекаются —
   «все варианты требуют дополнительной проверки».
3. Иначе сравнение по минутам в аномалии и на высоких широтах, затем
   по сближениям внутри окна.
4. Разница в пределах неопределённости — «варианты равнозначны».

Сокращение длительности показывается как **изменение плана**, не как
улучшение при прежних условиях.

## 6. Стык между половинами

Ровно два места, оба — типы в `vkd/types.py`.

**Место первое.** Codex выдаёт `TrajectoryPoint`:

```
t_utc, lat_deg, lon_deg, alt_km, L, B_over_B0, cutoff_GV, in_saa
```

плюс `EnvironmentSample` по каждому источнику:

```
t_utc, value, unit, source_id, published_utc, valid_from_utc, valid_to_utc, kind
```

где `kind` ∈ {observation, external_forecast}.

**Место второе.** Claude выдаёт `WindowAssessment` и `Recommendation`.
Codex их не считает.

## 7. Правила кода

0. Имена файлов и путей — только латиница, цифры, дефис, подчёркивание.
1. **Никаких молчаливых клампов.** Значение вне области — отказ с сообщением.
2. Единицы в имени переменной.
3. Каждая физическая константа с источником в комментарии.
4. Типы в `vkd/types.py` заморожены, меняются по согласованию.
5. Получение данных, расчёт и интерфейс — три разных пакета, не смешивать (Т7).
6. Настройки и ключи вне кода, в `.env` и `config.toml` (Т7).
7. **Пропуск данных ≠ нулевой риск.** Три состояния: воздействие есть,
   воздействия нет, данных недостаточно.
8. Отказ источника не даёт ложного «благоприятно» (Т6).
9. Тесты на инварианты, не на значения.

## 8. Обязательные тесты

| тест | что ловит | критерий |
|---|---|---|
| поворот модели в изотропном поле не меняет интеграл | угловые веса | О7, если делаем скафандр |
| секторная сумма полусферы = табличная полусфера ОСТ | ядро свёртки | О7 |
| **среднее по орбите через прил. А = таблица прил. К** | нормировка среды | Т3 |
| **отсечка: результат не меняется от данных после момента** | временная честность | Т4 |
| **отключённый источник → статус «недостаточно», не «благоприятно»** | надёжность | Т6 |

Три последних — обязательные, первые два — если дошли до скафандра.

---

## 9. Чего не заявляем

- допустимость реального выхода — за уполномоченными специалистами;
- вероятность разгерметизации — нет валидированного уравнения пробоя ткани;
- вероятность попадания фрагмента в космонавта из сближения — сближение о станции;
- дозу человека как обязательный результат — это дополнительная функция с оговорками;
- поток GOES как поток у станции без обрезания.

## 10. Исторический режим

Период: **1 мая — 30 июня 2024**. Выраженное событие: **буря Гэннон,
10–11 мая 2024, Kp 9,0**. Контроль: тихая неделя июня.

Два режима, различимые в интерфейсе:

- **разбор** — по всему доступному сегодня архиву;
- **прогноз из прошлого** — только по записям с `published_utc` ≤ момент
  отсечки; всё позже — только для проверки, не для расчёта.

Источник без времени публикации помечается **непригодным для строгого
воспроизведения**. Орбита периода — из TLE того периода; современная не подменяет.

## 11. Форма и сдача

Веб-сервис на Python, развёрнут по ссылке, доступ жюри до конца проверки.
Выгрузка: архив с отчётом и JSON, внутри параметры запроса, момент отсечки,
оценки по факторам, рекомендация, версии источников, версия алгоритма.
Сведения в выгрузке совпадают с интерфейсом.
