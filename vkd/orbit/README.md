# A3 — орбита для стыка B1

```python
from datetime import datetime, timezone
from vkd.orbit import trajectory, trajectory_with_provenance

start = datetime(2024, 5, 3, 12, tzinfo=timezone.utc)
meta, points = trajectory(start, 1920, 24000)
# Полный отчёт исходных записей для экспорта:
meta, points, provenance = trajectory_with_provenance(
    start, 1920, 24000, mode="history_review"
)
```

Три позиционных аргумента и добавленный `tle_path=None` совместимы с B1
из `origin/main` на `386ed17`. `tle_path` использует переданный снимок в live;
в истории применяется OEM, а не текущий TLE. Переданные TLE проверяются по
контрольным суммам, ID станции и возрасту; SHA включён в provenance.
Возвращаются существующие `TrajectoryMeta`, `TrajectoryPoint` версии 2.1.
`meta.frame` — исходная система TEME/EME2000; выходная — WGS84, отдельно в provenance.
`trajectory_with_provenance` — дополнительный отчёт данных для сборки
общего Manifest владельцем B1, не новый общий тип Recommendation.
`provenance.records` содержит `raw_record_id`, `source_id`, путь к оригиналу,
SHA-256 и метаданные. Коэффициенты поля тоже входят в этот реестр.
Для повтора передать `oem_raw_record_id` выбранного OEM и
`expected_record_hashes={rid: record['sha256'] for rid, record in provenance['records'].items()}`.
При изменении исходников или набора входов расчёт откажет с явной ошибкой.
Выгрузку этих полей и восстановление файлов выполняет потребитель Б.

## Режимы и происхождение

| Режим | Орбита | Условия |
|---|---|---|
| `auto` | Для старта в мае–июне 2024 — OEM, иначе SGP4 | Удобство совместимости B1; не выбор строгого прогноза |
| `history_review` | NASA/JSC OEM, EME2000/UTC | Явная реконструкция, `is_reconstruction=True`; создание и S3 LastModified не позднее заданной отсечки/старта |
| `history_forecast` | Только OEM с доказанной исторической доступностью | Обязателен `cutoff_utc <= start_utc`; публикация и доступность не позднее отсечки |
| `live` | TLE ISS → SGP4/WGS72 | SHA и контрольные суммы TLE, NORAD 25544, весь интервал в пределах допустимого возраста |

У нынешних 26 OEM публичная доступность в 2024 году не доказана:
строгий режим выдаёт `OrbitDataError`, а не подставляет текущие TLE.
Создание файла, время орбитального вектора и время скачивания раздельны.
Для TLE, полученного после старта расчёта, также ставится признак реконструкции.
Один OEM должен покрывать весь запрос; экстраполяция и заполнение разрывов
другим источником без явного указания запрещены.

Потребителю B1 необходимо передать выбранные пользователем режим и отсечку
именованными аргументами. Трёх аргументов недостаточно для строгой истории.
Исключения недоступности следует превратить в явный статус отсутствия
орбиты; не перехватывать их как разрешение использовать заглушку.

## Сетка, координаты и поле

- `minutes`: целое от 1 до 1920. Шаг по умолчанию 60 с, начало **и конец**
  включены: 32 часа дают 1921 точку. `step_seconds` допускает 1–600 с;
  последняя точка добавляется точно, даже если шаг не делит интервал.
- Положение/скорость OEM: кусочная кубическая интерполяция Эрмита;
  исходные векторы в км и км/с. Защитный предел разрыва узлов — 300 с.
  Преобразование EME2000 → ICRS с frame bias → ITRS средствами Skyfield;
  широта/долгота/высота геодезические WGS84, градусы/км.
- SGP4 использует WGS72 согласно TLE; выходная геодезия — WGS84.
  Возраст проверяется по обеим границам всего запроса, по умолчанию 3 суток
  относительно эпохи. Это инженерный предел, не гарантия ошибки положения.
- `B_nT`: полная внутренняя модель IGRF до степени 13, на времени каждой
  точки. Для 2024 используется IGRF-13; с 2025 — IGRF-14. За временными
  границами таблицы коэффициентов — отказ, без экстраполяции.
- `L`, `B_over_B0`, `cutoff_GV`: согласованное приближение центрального
  наклонённого диполя из первой степени той же IGRF. Статусы —
  `MagMethod.DIPOLE` / `approximation`. Это **не трассировка McIlwain L**.
  Отношение дипольных полей не смешивается с полным `B_nT` IGRF.
  Вертикальное обрезание Стёрмера — приближение, не расчёт направленной
  геомагнитной прозрачности во время бури и не интерполяция таблицы ОСТ.
- `in_saa`: заданный извне порог модуля поля, не официальная граница SAA.
  Внешнее магнитное поле бури и прогноз манёвров станции не моделируются.

Для интегрирования по окнам используются фактические интервалы между
точками; конечная точка не добавляет лишнюю минуту экспозиции. Если граница
окна не лежит на сетке, необходимо отдельно получить её значение.

Модуль работает без сети. Обновление TLE с метаданными/хешем относится к A4;
текущий снимок быстро устаревает. Skyfield использует встроенную таблицу
времени UT1/секунд координации; внешние параметры движения полюса здесь
не загружаются. Сантиметровая точность геодезии не заявляется.

## Проверки и пределы доказательства

`python -m pytest tests/orbit -q`:

- опубликованные векторы AIAA 2006-6753 для ближней и дальней орбиты;
  координаты SGP4 до `1e-7` км, скорости до `1e-8` км/с относительно эталона;
- чтение всех 26 OEM и точное восстановление выбранных исходных узлов;
- аналитическая круговая орбита: погрешность кубической интерполяции
  при исходном шаге 240 с меньше 100 м. Это тест интерполятора на идеальной
  орбите, **не измеренная ошибка NASA OEM относительно реальной МКС**;
- независимый синтез IGRF через pyIGRF 0.3.3 с теми же коэффициентами,
  шесть пространственно-временных случаев, допуск 1 нТ. Это численная
  проверка метода, не сравнение с измеренным полем;
- шесть стартов мая–июня 2024, по 32 часа каждый, полное покрытие,
  происхождение, конец горизонта, согласованность сеток 30/60 с;
- отказы для устаревших TLE, неизвестной исторической публикации,
  некорректных входов и неподдерживаемых систем координат/времени.

Эталонные файлы, контрольные суммы и воспроизведение независимого расчёта:
`tests/orbit/fixtures/README.md`. Библиотека pyIGRF нужна только при
перегенерации сохранённого эталона и не добавлена в runtime-зависимости.
Установленные версии текущей проверки — `data/orbit/validation_environment.json`;
это отчёт окружения А, не общий lock двух участников.

Критерии A3/Т2/Т3/Т4/Т6 поддерживаются вычислением, эталонами,
происхождением и отказом при недоступности. Приёмка всего приложения,
развёртывание и достаточность оценки всех механизмов остаются отдельными
совместными проверками.

## A3 v2: положения и скорости для сезонной модели

В `trajectory_with_provenance` доступен флаг `include_inertial_states=True`.
Он добавляет `provenance['inertial_states']` версии `orbit-inertial-states-1`:
EME2000/J2000, центр Земли, км и км/с, одна сетка с `TrajectoryPoint`,
связь каждой строки с исходным файлом/сегментом, версии и хеш содержимого.
Без флага прежние точки и сигнатура результата сохранены; общие типы не менялись.
OEM-скорость — производная интерполяции по исходным r/v; SGP4-скорость
преобразована вместе с положением из TEME, не вычислена из широты/долготы.

Непрерывность OEM проверяется и между узлами выходной сетки: крупный шаг
больше не скрывает пропуски. Байты TLE повторно сверяются с receipt
непосредственно перед передачей в SGP4. Неизвестная историческая доступность
по-прежнему не допускает строгую орбиту.

Стык, пример, ограничения и действия Б:
[A3_STATES_HANDOFF.md](../../docs/integration/A3_STATES_HANDOFF.md).
Независимый расчёт преобразования ERFA сохранён в фикстуре; pyerfa нужен
только для её перегенерации, не для приложения или обычного pytest.
