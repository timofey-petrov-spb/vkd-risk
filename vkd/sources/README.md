# A4 — текущие источники

Приложение Б автоматически импортирует `goes_latest`, `kp_latest`, `tle_latest`
из `vkd.sources`. Сигнатуры совместимы с существующим стыком:

```python
from vkd.sources import goes_latest, kp_latest, tle_latest, noaa_latest

goes, goes_raw, goes_fetch = goes_latest(disabled=False)
kp, kp_raw, kp_fetch = kp_latest(disabled=False)
tle_text, tle_fetch = tle_latest(disabled=False)  # именно два значения
forecasts, forecast_raw, forecast_fetch = noaa_latest(disabled=False)
```

GOES/Kp — `EnvironmentSample | None`; NOAA — tuple из `EnvironmentSample`.
Функции не возвращают нули вместо пропусков. `Fetch.payload is None` означает,
что данные нельзя использовать как текущие. `ok` — успешное получение и
разбор по сети, **не** достаточность данных для рекомендации. При устаревании
успешного ответа `ok=True`, но `status='stale'` и численного результата нет.

## Времена, единицы и ограничения

| Источник | Результат | Допуск давности по умолчанию | Обычный интервал запросов |
|---|---|---|---|
| NOAA primary GOES | ≥10 МэВ, `pfu = протон/(см²·с·ср)`, 5-минутное усреднение | 60 мин от измерения | 5 мин |
| GFZ Kp | последний завершённый UTC-интервал 3 ч, безразмерный индекс | 6 ч от конца интервала | 15 мин |
| CelesTrak ISS | TLE NORAD 25544, эпоха отдельно от публикации | 3 суток от эпохи; A3 дополнительно проверяет весь горизонт | 2 ч, также при ручном обновлении |
| NOAA 3-day forecast | `kp_forecast` (3 ч) и `s1_prob_daily` (% за сутки) | 36 ч от Issued и не истёкший горизонт | 1 ч |

Допуски давности — настройки пригодности прототипа, не отраслевые нормативы
и не гарантии физической точности. `max_age_min` можно передать явно.
Свежий GOES не обеспечивает прогноз на будущие 32 часа и не измеряет дозу
на орбите МКС. Потребитель сам проверяет покрытие каждого окна.

У GOES/Kp/TLE неизвестна точная публикация: `published_utc=None`. Время
получения доказывает только наличие именно этих байтов к этому моменту;
оно не подменяет историческую публикацию. У NOAA используется `Issued`.
HTTP `Date`, `Last-Modified`, эпоха TLE и mtime не становятся публикацией.

GFZ датирует **начало** 3-часового интервала. У нас `t_utc` — конец,
`valid_from_utc/valid_to_utc` — исходные границы. Ещё не завершённый
nowcast исключается, `pre` остаётся preliminary, `def` — final.
Кеш разбирается на время его получения: старый незавершённый nowcast
не превращается автоматически в завершённое наблюдение после ожидания.

GOES выбирается по энергии, времени и спутнику; отрицательные, NaN/Inf,
будущие и некорректные строки отбрасываются с аудитом. Неизвестные флаги
качества требуют отдельной документированной трактовки, поэтому такие
строки не принимаются. Конфликт разных значений на последнем времени
даёт отказ. Длительность действия последнего наблюдения не выдумывается.

В NOAA сохраняются исходные ячейки, включая границы суток и вероятности.
Их надо пересечь с окнами запроса и вычислить покрытие. Суточная вероятность
не переводится в вероятность за длительность ВКД и не создаёт событие.
`noaa_latest` подготовлен для Б; в `2d20793` приложение подключает NOAA
только в истории. Добавить текущий вызов должен интегратор.

## Кеш и отказы

По умолчанию `data/cache/sources/` (игнорируется Git). Для отдельного
экземпляра можно передать `cache_dir`. `raw/<SHA-256>.bin` содержит точные
байты тела ответа после HTTP content-decoding, receipt — URL, хеш,
размер, время получения, версию парсера, параметры пригодности и аудит.
Каждое чтение проверяет SHA/размер и повторяет разбор. Ручное изменение
raw, неполная запись или неизвестное время не принимаются.

Запись атомарная; блокировка одного источника через `flock` предотвращает
одновременные запросы из процессов/сессий на macOS и Linux. Занятая
блокировка немедленно возвращает кеш/нет данных. Отключение — аргумент
конкретного вызова, не глобальный флаг; пригодный кеш остаётся доступным.
Кеш не очищается автоматически: сохранённые расчёты должны экспортировать
raw, и квота/очистка постоянного хранилища остаётся задачей развёртывания.

Тайм-ауты подключения/чтения 3,05/6 с, максимум 2 попытки с паузой 0,25 с
для транспортной ошибки и некоторых 5xx. Пустой HTTP 200, испорченный
ответ, 403, 429 и тайм-аут имеют разные `Fetch.error`. `Retry-After`
сохраняется; ручное обновление не обходит паузу после отказа.
Лимит ответа 4 МиБ. Более старый ответ сервера не вытесняет новые данные.
При чтении чанков также проверяется общий предел 12 с на попытку;
один уже начатый read может дополнительно занять до своего тайм-аута 6 с.

Для CelesTrak — одна попытка, без автоматического следования редиректу
или повторов при любом non-200; двухчасовой предел сохраняется после
ошибки. Это требование [политики CelesTrak](https://celestrak.org/usage-policy.php).
Встроенный TLE A3 может служить резервом, только если SHA и давность
подходят; время берётся из его манифеста, не из mtime. Отсутствие нового
TLE не прикрывается историческим OEM или произвольной круговой орбитой.

Дополнительные аргументы: `force_refresh=True` — ручное обновление
GOES/Kp/NOAA вне обычного интервала, `now`/`transport` — проверочные входы,
`use_bundled=False` — запрет встроенного TLE. Защита от квот действует
и при `force_refresh=True`. Недоступный для записи кеш даёт явный отказ;
это надо показать в диагностиках площадки.

## Передача происхождения в Б

`raw[sample.raw_record_id]` содержит `metadata`, `encoding='base64'`,
`content_base64` и выбранную исходную строку. Этот объект самодостаточен
для проверки SHA без доступа к локальному кешу. Метаданные нужно положить
в `Manifest.source_versions[source_id][raw_record_id]`.
`Fetch.metadata` и `Fetch.raw` доступны и для TLE. Орбитальный мост Б
пока сохраняет нормализованный TLE отдельным объектом; экспортировать
исходный A4 receipt дополнительно, чтобы не терять оригинальные байты.

Словари каждого вызова независимы. Нет общих изменяемых результатов,
настроек отключения или файлов `current.tle`, перезаписываемых сессиями.
Кеш и ограничения частоты общие только в пределах конкретного cache_dir.
